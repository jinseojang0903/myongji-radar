# tests

판정 규칙(`site/js/rules.js`)과 자연어 해석기(`site/js/parser.js`), 파이프라인 검증 함수 테스트.

## 실행

Node 22 이상. 외부 패키지는 없다.

```
npm test
```

- `rules.test.js`: 판정 규칙. 기준은 `docs/api-contract.md` 3절. 마지막 테스트는 무작위 5만 건으로 "불가인데 가능" 판정이 없는지 본다.
- `parser.test.js`: 자연어 해석기. 기준은 계약 2절. 여기 문장은 해석기를 만들며 쓴 개발용이라 정확도 측정에 쓰지 않는다 (정확도는 `npm run eval:parser`). 무작위 문장 2만 개로 출력 형식도 본다. 측정 스크립트 `eval/parser/run.js`의 CSV 읽기·채점도 여기서 시험한다.
- `recommend.test.js`: 맞춤 추천. 시연 시나리오(자연캠 2학년 재학생 혼자 → AI 리터러시 신청 가능, 해커톤 불가), 문장이 말한 조건만 바꾸기, 기간 필터(마감일 기준), 4상태 묶기·정렬, 칩 상한, 저장된 조건 지우기.
- `detail.test.js`: 카드 상세(항목 표·근거·마감 변경 이력·문의 초안), 캘린더 파일(RFC 5545 형식, 시각 미기재는 하루 종일, 공지 문자열 이스케이프), 내 조건 저장(해석된 값만, 깨진 값은 무시).
- `log.test.js`: 제작 기록. `site/data/log.json` 형식, 모든 수치에 측정일·출처가 있는지(지어낸 수치 금지), 가리키는 파일이 저장소에 있는지, 검수 체험 채점.
- `export_contract.test.js`: 파이프라인 내보내기(`pipeline/exporter`)가 만든 결과 파일이 사이트의 형식 검사·판정·화면 계산·캘린더를 그대로 통과하는지 (파이프라인과 사이트가 같은 계약을 보는지).
- `a11y.test.js`: 접근성(#27) 가운데 코드로 고정할 수 있는 것. 글자·배경 대비 4.5:1(CSS 색 변수로 계산), 포커스 표시·입력창 경계 3:1(남색 머리글 안은 흰 포커스), 네 화면의 언어·제목·확대 허용·랜드마크·라벨, 좁은 화면에서 표·버튼이 화면을 가로로 밀지 않는 규칙, 가로로 밀리는 표를 키보드로 닿는 영역으로 감쌌는지. 실제 폭 측정은 `site/README.md` 기록.
- `cards.test.js`: 홈 화면 계산(마감·D-day·카드 배지·필터·정렬), 외부 링크 검사, 데이터 읽기, 예시 데이터(`site/data/cards.sample.json`)가 계약 형식을 따르는지와 판정 결과가 화면 설계와 같은지.
