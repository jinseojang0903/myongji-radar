# 자연어 해석기 시험 문장 (#23)

맞춤 추천 화면에서 학생이 쓰는 문장을 해석기(`site/js/parser.js`)가 조건으로 얼마나 정확히 바꾸는지 잰다. 결과는 제작 기록 탭과 결선 발표의 근거가 된다.

> **중요: 해석기 코드(`site/js/parser.js`)와 개발용 문장(`tests/parser.test.js`)을 보지 않고 쓴다.**
> 해석기는 Claude가 표현 사전으로 만들었다. 사전을 보고 문장을 쓰면 사전에 있는 표현만 쓰게 되어 정확도가 실제보다 높게 나온다. 실제 학생이 입력창에 칠 법한 말로 쓴다. 아래와 계약 문서의 예시 문장도 **그대로 쓰지 말고** 다른 표현으로 쓴다 (예시는 개발할 때 이미 시험했다).
>
> 문장 속 학생은 **가상의 학생**으로 쓴다. 자기 이름·학번·연락처나 실제 학적 사정을 넣지 않는다 (문장은 공개 저장소와 측정 결과에 그대로 남는다).
>
> 정답을 고르는 기준은 `docs/api-contract.md` 2절 "해석 규칙"이다. 이것은 봐도 된다 (기준이 다르면 해석기와 정답이 다른 것을 재게 된다).

## 누가 무엇을

| 사람 | 할 일 |
|---|---|
| 작성자 (정답표 담당 팀원) | `sentences.csv`를 채워 저장소에 올린다 (PR, 또는 팀장에게 파일 전달). 측정 스크립트는 실행하지 않아도 된다 |
| 측정자 (팀장) | `npm run eval:parser`로 측정하고 결과 파일을 커밋한다. **결과를 보기 전에는 사전을 고치지 않는다** |

## 파일

| 파일 | 내용 |
|---|---|
| `sentences.csv` | 시험 문장과 정답. 한 줄 = 한 문장 |
| `run.js` | 측정 스크립트 |
| `runs/` | 문장이 50개 다 찬 측정마다 한 파일씩 쌓인다 (`날짜시각_v해석기버전.json`). **가장 이른 파일이 발표에 쓰는 정확도** (50개 미만 측정은 남기지 않는다) |
| `result.json` | 가장 최근 측정 결과 |

### 파일 저장

엑셀에서 열어 채우고 **파일 → 다른 이름으로 저장 → "CSV UTF-8(쉼표로 분리)"** 를 고른다. 그냥 "CSV(쉼표로 분리)"로 저장하면 한글이 깨진다 (스크립트가 깨진 파일을 알려 준다). 구글 시트는 "파일 → 다운로드 → CSV".
첫 줄(제목 줄)은 지우지 않는다. `example-`로 시작하는 두 줄은 견본이라 채점하지 않는다 (남겨 둬도 된다).

## 열 쓰는 법

말하지 않은 조건은 **비워 둔다**.

| 열 | 쓰는 법 |
|---|---|
| `id` | `s01`~`s50` |
| `sentence` | 학생이 입력할 문장 그대로 (200자 이내). 띄어쓰기·말투·줄임말도 실제처럼 |
| `campus` | `인문` / `자연` (인문캠퍼스는 서울, 자연캠퍼스는 용인) |
| `grade` | 숫자 `1`~`6` ("신입생"·"새내기"는 1) |
| `is_transfer` | 편입생이라고 했으면 `예`, 편입생이 아니라고 했으면 `아니오` |
| `enrollment` | `재학` / `휴학` / `수료` / `초과학기` / `졸업유예` |
| `participation` | `개인` / `팀` (둘 다 괜찮다고 했으면 비움) |
| `deliverables` | `기획서·제안서`, `영상`, `에세이·수기`, `코드·개발`, `발표`, `디자인`, `현장 참가` 중에서. 여러 개면 쉼표로 (`영상,디자인`) |
| `period` | 마감일 기준. `마감임박`(마감 7일 이내) / `이번주`(이번 주 일요일까지) / `이번달`(이번 달 말일까지) |
| `unknown` | 학생이 **조건으로 말했지만 위 칸에 담을 수 없는 표현**을 문장에서 그대로 베껴 쓴다. 부정어·시간 표현이 붙어 있으면 함께 쓴다(그 낱말이 빠지면 뜻이 달라지므로). 여러 개면 쉼표로. "대회", "있어?" 같은 조건이 아닌 말은 적지 않는다 |
| `writer` | 작성자 이니셜 (필수. 저장소가 공개라 실명은 쓰지 않는다) |
| `written_at` | 작성일 `YYYY-MM-DD` (필수) |
| `note` | 정답이 애매했던 이유 (선택) |

### 애매할 때 (계약 2절 해석 규칙 요약)

- 뜻이 하나로 정해지지 않으면 칸은 비우고 `unknown`에 적는다. 학년 범위("○학년 이상"), 지금이 아닌 상태("○○할 예정", "작년에는"), 학과 이름이 여기에 든다. 대회 일정·학생의 형편("이번 겨울방학에", "다음 주는 바빠서")은 지금 상태를 바꾸지 않으므로 캠퍼스·학년 칸을 비우지 않는다. 다만 계약 2절 3의 시간 표현 목록("내년", "다음 학기", "전에" 등)이 있으면 일정을 말할 때도 비운다.
- 같은 조건이 둘 이상이면 칸은 비우고 둘 다 `unknown`에. 제출물은 여러 개를 모두 적는다.
- 편입·참가 형태의 부정은 반대 값으로 적는다 (편입생이 아니라고 하면 `아니오`, 팀이 싫다고 하면 `개인`). 그 밖의 조건을 부정하면 `unknown`에.
- 싫다·별로·부담된다는 말은 참가 형태(팀이 싫다 → `개인`)에서만 반대 값으로 적고, 다른 조건에서는 칸을 비운다.
- 무엇을 부정하는지 사람이 읽어도 헷갈리면 칸을 비우고 `unknown`에 적는다.

## 고르게 섞기 (권장)

50개를 아래처럼 나누면 해석기의 약한 곳이 드러난다. 정확한 개수를 맞출 필요는 없다. 예시 문장은 일부러 적지 않았다 (위 "중요" 참고).

| 종류 | 개수 |
|---|---|
| 조건 1~2개, 짧은 문장 | 10 |
| 조건 3개 이상 | 15 |
| 위 칸에 담을 수 없는 조건이 섞임 (학적·신분·전공·기간 등) | 10 |
| 부정이나 거절이 섞임 | 5 |
| 같은 조건이 둘 이상이거나 애매함 | 5 |
| 말투가 다양함 (존댓말, 반말, 오타, 줄임말) | 5 |

## 측정 (팀장)

```
npm run eval:parser
```

- 문장이 없으면 "측정 중"만 나온다. 형식이 틀린 줄이 있으면 엑셀 행 번호와 함께 알려 주고 멈춘다. 50개보다 적으면 경고한다.
- `unknown` 채점: 정답에 적은 낱말이 모두 해석기 문구에 들어 있으면 찾은 것이다. 해석기 문구가 앞뒤 낱말을 더 담아도 감점하지 않는다. 한계: 낱말 일부만 겹치면("고학년"과 "학년") 다르게 본다.
- 결과: 항목별 정확도와 틀린 방식(다른 값 / 비움 / 말하지 않은 값), **판정 조건을 틀린 값으로 읽은 수**(가장 나쁜 오류: 판정이 틀어질 수 있다), 문장 전체 일치율, 이해하지 못한 표현을 찾은 수, 틀린 문장 목록.
- **측정 뒤 사전을 고치면** 그 문장은 더 이상 "보지 않은 문장"이 아니다. 다시 잰 숫자는 "사전 보완 후"로 따로 적고, `runs/`의 첫 파일 숫자를 발표의 정확도로 쓴다.
- **계약 2절을 고쳐 정답이 바뀌면** 바뀐 정답은 해석기 코드를 보지 않은 사람이 새 계약으로 다시 매긴다. `note` 맨 앞에 "계약 수정(#이슈)"과 바뀐 이유를 적고, 이전 판단은 "(수정 전: …)"으로 남긴다. 다시 매긴 사람과 바뀐 문장은 아래 기록에 적는다. 다시 잰 숫자는 "계약 수정 후"로 따로 적는다. 정답을 측정 결과를 본 뒤에 고쳤으므로 **발표의 정확도는 그대로 `runs/`의 첫 파일**이다.
  - 2026-11-09 (#37): 일정 표현은 지금 상태를 비우지 않도록 계약을 고쳐 s08·s16·s50의 캠퍼스·학년을 채웠다. 해석기 코드를 보지 않은 Claude 에이전트가 50문장 전부를 다시 확인했다.
