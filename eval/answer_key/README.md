# 정답표 작성 방법 (#7)

AI 추출 결과를 채점하는 기준이다. **사람이 원문을 직접 보고** 만든다. 모델 비교(#9), 프롬프트 개선, 결선 발표의 정확도 수치가 모두 이 정답표에서 나온다.

> 중요: AI가 만든 카드를 보고 고치는 방식으로 만들지 않는다. AI 결과를 먼저 보면 그 값에 끌려가 채점이 후해진다. **원문만 보고** 채운다.
>
> 값을 고르는 기준은 AI 지시문(`prompts/extract_v0.2/system.md`)과 **똑같다.** 기준이 다르면 정답표와 AI가 다른 것을 재게 된다. 애매하면 system.md를 따르고, system.md로도 정할 수 없으면 `needs_check`로 두고 이슈에 남긴다.

## 파일

| 파일 | 내용 |
|---|---|
| `sources.csv` | 대회별로 참고한 공지 목록 (대회 하나에 공지가 여러 개일 수 있음) |
| `answers.csv` | 대회 × 항목 15개의 정답. 한 줄 = 한 항목 |

엑셀이나 구글 시트에서 열어 채우고, **CSV UTF-8** 로 저장한다. 첫 줄(제목 줄)은 지우지 않는다.
`answers.csv`에 들어 있는 `example-id` 15줄은 **항목 목록 견본**이다. 대회마다 이 15줄을 복사해 `contest_id`만 바꿔 쓰고, 다 쓰면 `example-id` 줄은 지운다 (채점 스크립트는 `example-id`를 건너뛴다).

## sources.csv

| 열 | 쓰는 법 |
|---|---|
| `contest_id` | 대회 구분용 짧은 영문 이름. 예: `ai-literacy-2026`, `evc-13-nature`, `history-video-5`, `abix-hackathon-2026` |
| `notice` | 이 대회 안에서 공지 번호 1, 2, 3… (**게시일이 이른 것부터**. AI 입력의 공지 번호와 같다) |
| `board` | 게시판 이름 (예: 메인 일반공지) |
| `posted` | 게시일 `YYYY-MM-DD` |
| `url` | 원문 주소 |
| `title` | 공지 제목 |

## answers.csv

대회마다 아래 15개 항목을 한 줄씩 쓴다. 공지에 없는 항목도 줄을 지우지 말고 `flag`를 `missing`으로 둔다.

| 열 | 쓰는 법 |
|---|---|
| `contest_id` | sources.csv와 같은 이름 |
| `field` | 항목 이름 (아래 표의 영문 그대로) |
| `value` | 아래 "값 쓰는 법"대로. 정보가 없으면 비움 |
| `flag` | `found`(찾음) / `missing`(공지에 없음) / `needs_check`(애매함) / `conflict`(같은 시점 출처끼리 다름) |
| `quote` | 근거 문장을 원문 그대로 복사. 근거가 여러 개면 ` ‖ `(공백, 세로선 두 개, 공백)로 구분 |
| `notice` | 근거별 공지 번호. 여러 개면 `quote`와 **같은 순서로** `1 ‖ 2` |
| `location` | 근거별 `제목` / `본문` / `이미지` / `첨부`. 여러 개면 같은 순서로 ` ‖ ` |
| `file` | 근거별 이미지·첨부 파일 이름 (제목·본문이면 비움). 여러 개면 같은 순서로 ` ‖ ` |
| `note` | 애매한 이유, 충돌 내용, 고르지 않은 다른 값 (마감 연장 전 값 등) |
| `checker` | 작성자 이름 |
| `checked_at` | 작성일 `YYYY-MM-DD` |

### 값 쓰는 법 (AI 출력 형식 `prompts/extract_v0.2/schema.json`과 1:1)

| field | 값 예시 | 규칙 |
|---|---|---|
| `title` | `AI 리터러시 경진대회` | 공식 이름. 게시판 말머리·"개최 안내" 제외 |
| `organizer` | `교수학습센터` | 공지에 적힌 가장 구체적인 주관 부서 (상위 기관 생략) |
| `scope` | `교내` 또는 `외부` | 명지대 부서·사업단 주관이면 교내 |
| `kind` | `모집` / `연장` / `변경` / `취소` / `결과` / `기타` | 공지가 여러 개면 **가장 늦게 게시된 공지**의 성격 |
| `apply` | `2026-10-01 ~ 2026-10-21 15:00` | 참가 신청 기간. 시각이 없으면 날짜만 (`2026-09-14 ~ 2026-10-23`). 한쪽 날짜가 없으면 `~ 2026-10-23`. 시각을 채우지 않는다. 연도를 추정했으면 note에 |
| `stages` | `신청: 2026-09-14 ~ 2026-10-23 ‖ 출품: ~ 2026-11-11` | `이름: 시작 ~ 끝`을 날짜 순으로. **apply가 있으면 `신청` 단계를 반드시 같은 날짜로 넣는다.** 이름: 신청·출품·예선·본선·발표·시상·기타. 같은 이름이 두 번이면 둘 다 쓴다 |
| `campus` | `any` / `인문` / `인문,자연` | `any`는 대상 문장이 있는데 캠퍼스로 나누지 않을 때 |
| `grades` | `any` / `1,2` | campus와 같은 규칙 |
| `enrollment` | `허용: 재학 / 제외: 휴학, 수료, 초과학기, 졸업유예, 대학원생` | 대상 문장은 있는데 학적 언급이 없으면 `허용: / 제외:` (빈 목록), 대상 문장이 없으면 비우고 `missing`. 낱말: 재학, 휴학, 수료, 초과학기, 졸업유예, 졸업, 대학원생, 편입생, 기존 수상자 |
| `team` | `~3, 개인 가능` / `2~5, 개인 불가` / `제한 없음, 개인 모름` | `최소~최대, 개인 가능/불가/모름`. 공지에 없는 숫자는 비움 ("3인 이내" → `~3`). 인원 제한이 없다고 **적혀 있으면** `제한 없음` |
| `deliverables` | `기획서·제안서, 발표 ‖ 예선 제안서 최대 3장, 결선 발표 PPT` | `태그(쉼표로 여러 개) ‖ 원문 요약`. 태그: 기획서·제안서, 영상, 에세이·수기, 코드·개발, 발표, 디자인, 현장 참가, 기타 |
| `benefits` | `대상 1팀 총장상·100만원, 최우수 1팀 60만원, 우수 2팀 40만원` | |
| `mileage` | `창의 ‖ 10 ‖ 예선 참가자 전원 창의 10점` | `영역 ‖ 참가자 점수 ‖ 원문 요약`. 모르는 칸은 비움. 수상자 추가 점수는 요약에만 |
| `how_to_apply` | `MYiCap+ 신청 시 zip 업로드 ‖ https://...` | `요약 ‖ 신청 링크(없으면 비움)` |
| `contact` | `교수학습센터 ‖ ctl@mju.ac.kr ‖ 02-300-1669` | `부서 ‖ 이메일 ‖ 전화`. 공지에 적힌 것만. 담당자 개인 이름은 쓰지 않는다 |

### 공지·출처끼리 값이 다를 때 (system.md 4절과 같음)

- **나중 공지가 바꾼다고 밝힌 값**(연장·변경): 나중 공지 값을 쓰고 `flag`는 `found`, 이전 값은 `note`에 (예: `이전 마감 2026-09-30 (공지 1)`).
- **같은 시점 출처끼리 다른 값**(같은 공지의 본문과 포스터 등): `flag`는 `conflict`.
  - 제외 대상·제출물 태그: **합친다.**
  - 허용 캠퍼스·학년·학적, 개인 참가 가능: **더 좁은 쪽**을 쓴다.
  - 날짜·인원처럼 하나를 고르는 값: 본문 → 첨부 → 이미지 순으로 고르고 나머지는 `note`에.
- 연도가 없는 날짜: 게시 연도를 쓰되, 게시월보다 이른 월이면 다음 해로 쓰고 `needs_check`.

## 채점 방식 (#9가 구현)

- 읽을 때는 `utf-8-sig`(엑셀이 붙이는 BOM 처리), `example-id` 줄은 건너뛴다.
- **자동 비교 항목:** scope, kind, apply, stages, campus, grades, enrollment, team, deliverables 태그, mileage 점수, contact 이메일. 표기를 정규화한 뒤 같으면 정답.
  - campus `인문,자연`과 `any`, grades `1,2,3,4`와 `any`는 **같은 값으로 본다** (누가 신청할 수 있는지가 같다).
- **사람 판정 항목:** title, organizer, benefits, deliverables 요약, mileage 원문, how_to_apply. 뜻이 같으면 정답.
- **중요 항목:** apply, campus, grades, enrollment, team. 신청 가능 여부 판정에 쓰이므로 따로 집계하고, **"불가인데 가능으로 만들 수 있는 오류"** 를 위험 오류로 센다.
- **flag는 두 방향을 모두 센다.**
  - 정답이 `missing`인데 AI가 값을 냄 → 지어낸 오류
  - 정답이 `needs_check`·`conflict`인데 AI가 `found`로 확정 → 과신 오류
  - 정답이 `found`인데 AI가 `needs_check`·`conflict` → 과잉 보류. 오류로 세지 않지만 **"확인 필요 비율"** 로 따로 보고한다 (모든 항목을 보류하면 쓸모가 없으므로).
  - `needs_check`와 `conflict` 사이의 차이는 같은 "확인 필요"로 본다.

## 대상 대회

예선 조사 12건(작업 폴더 `docs/02_조사_공지목록.md`) + 11월에 새로 올라온 대회 최소 5건. 12건 중 마감이 지난 대회도 정답표에 넣는다 (정확도 측정용). 대회가 아닌 공지(특강·채용 등)는 넣지 않는다. 그래서 `is_contest` 정확도는 이 정답표로 잴 수 없다.
