# 실행 스크립트

- `run_daily_collect.ps1`: 수집→규칙 분석. 전용 main 저장소에서 하루 1회 실행한다. `-ValidateOnly`는 네트워크 없는 설정 확인이다.
- `register_daily_collect.ps1`: 현재 사용자로 매일 한국시간 21시 예약 등록. `-WhatIf`로 사전 확인하고 `-Remove`로 해제한다.
- `check_live_cards.mjs`: 배포 직후 공개된 `cards.json` 점검(#98). `npm run check:live`로 기본 배포 주소를, `-- --file <경로>`로 로컬 파일을 본다. 화면과 같은 형식 검사, 예시 데이터가 남았는지, 생성 시각, 근거 상한(문장 200자·항목당 5개·카드당 1,500자), 휴대전화·학교 밖 메일·8자리 이상 숫자(내보내기처럼 전각·대시를 정규화한 뒤), https·허용 도메인 밖 링크, 사람 검수 전 문의 메일, 네 화면 파일이 열리는지를 본다. 출력은 계약 형식에 맞는 카드 id·알려진 항목 이름·건수만 남기고, 형식이 틀린 id나 예외 메시지는 위치 번호·고정 문구로 바꾼다. 종료 코드 0 문제 없음, 1 경고, 2 실패(못 읽음·예시 그대로·형식 오류·카드 0장·화면 파일 안 열림·점검 중 오류).
- `run_daily.ps1`: AI 추출→검증→카드 생성→배포까지의 연결은 #19에서 구현 예정이다. 현재 파일은 없다.

설치·작업 이름·로그·장애 확인과 이틀 운영 기준은 [자동 수집 운영](../docs/collector/자동수집_운영.md)을 따른다. 아직 실제 예약 등록과 이틀 연속 성공은 검증하지 않았다.
