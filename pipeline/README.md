# 명지레이더 수집과 분석 파이프라인

Python 프로젝트의 실행 위치다. 수집·규칙 분석·AI 추출·근거 대조·공개 카드 출력이 구현되어 있다. 다른 모델 교차 검증과 행사 병합은 후속 단계다. 최종 흐름은 수집 → 분류 → 추출 → 검증 → 병합 → `site/data/cards.json`이다. 데이터 계약은 [api-contract.md](../docs/api-contract.md)를 따른다.

총 11개 공개 게시판에서 글을 발견하고, 상세 페이지의 제목·본문·이미지·첨부 링크를 SQLite와 로컬 JSON에 저장한다. 구현 방향과 확장 계획은 [수집기 구현 계획](../docs/collector/수집기_구현계획.md)에 정리했다. 초기 추가 5곳의 실측 비교는 [추가 출처 검증 결과](../docs/collector/추가출처_검증결과.md), 나머지 4곳의 등록·검증은 [출처 추가 기록](../docs/collector/출처_추가대상.md)에 기록했다. 실행 코드와 설정은 이 폴더에, 설계·검증 기록은 `docs/collector/`에 둔다.

저장된 본문을 대상으로 활동 분류·날짜·참가 조건 언급을 추출하는 규칙 모듈도 구현했다. [규칙 분류 구현 결과](../docs/collector/규칙분류_구현결과.md)에 동작과 한계를 정리했다. AI 없이 동작하며 추출값은 검수 전이다.

## 후속 단계

수집·규칙 분석 다음에 이어지는 단계다. 구현된 범위와 남은 범위를 구분해 적는다. 세부 출력은 [데이터 계약](../docs/api-contract.md)을 따른다.

1. **추출 (#14, 구현됨: 모델 비교용 `eval`, 매일 실행용 `daily`):** Claude Code 헤드리스(`claude -p`)와 JSON 스키마 강제로 카드 정보를 추출한다. 모델·프롬프트 버전과 원문 근거를 남긴다. 아래 "AI 추출" 참고. 이미지·첨부 입력은 #12 뒤에 연결한다. 규칙·매일 AI 추출의 버전별 분석 저장은 #13으로 연결했다.
2. **검증 (#15, 근거 대조·상식 검사 구현됨):** 근거 문장이 원문에 있는지 대조하고 상식 검사를 한다. 다른 모델 교차 추출은 모델이 정해진 뒤에 붙인다. 아래 "추출 결과 검증" 참고.
3. **병합 (#16):** 여러 게시판의 같은 행사를 묶고 마감 변경 이력과 각 값의 출처를 보존한다.
4. **출력 (#17, 구현됨):** 공개할 요약·짧은 근거·원문 링크만 `site/data/cards.json`으로 내보낸다. 원문·첨부·DB는 로컬에 둔다. 아래 "cards.json 내보내기" 참고.
5. **운영 (#19):** 전체 파이프라인은 하루 1회 실행하고 사이트에 배포하는 안이다. 수집 단계의 실행 위치·시각과 잠금·로그·예약은 #31(매일 수집)이 맡는다. 그 다음 단계(추출 → 근거 대조 → cards.json)는 `python -m publisher`로 구현됨 (아래 "매일 공개"). 사이트는 Vercel이 `main`의 `site/`를 배포한다 (`site/README.md` "배포"). 새 cards.json을 `main`에 올리는 단계는 #19에서 정한다.

## 실행

### 매일 자동 실행

개인 Windows PC에서 매일 한국시간 21시에 수집→규칙 분석을 실행하는 스크립트를 추가했다. [자동 수집 운영 안내](../docs/collector/자동수집_운영.md)에 설치·등록·해제·중복 방지·로그·실패 처리와 실제 이틀 검증 절차를 정리했다. 현재 구현·오프라인 검증 단계이며 실제 예약 등록·이틀 자동 성공 기록은 아직 없다 (#31).

저장소 루트에서 다음으로 네트워크 요청 없이 사전 확인한다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_daily_collect.ps1 -ValidateOnly
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\register_daily_collect.ps1 -WhatIf
```

실제 등록은 PR 병합 후 전용 운영 저장소의 main에서 register_daily_collect.ps1을 실행한다. 해제는 같은 명령에 `-Remove`를 붙인다. PC 전원과 등록한 Windows 사용자 로그인 상태가 필요하다. 일일 실행은 하루 1회 시도를 제한한다. 기존 BAT 1·2번과 직접 collector run은 개발용으로 날짜 제한을 우회하므로 운영 중 추가 실행하지 않는다. 수집·내보내기·분석 CLI와 일일 실행은 같은 데이터 폴더 잠금을 공유한다.

손상된 일일 날짜 상태는 `pipeline/`에서 `.\.venv\Scripts\python.exe -m collector.daily --recover-state`로 복구한다. 원본을 비공개 백업하고 복구 당일은 차단한 뒤 다음 날 재개한다. 상태 파일을 삭제해 당일 재시도하게 만들지 않는다. 상세 확인·백업·복구 절차는 위 운영 안내를 따른다.

### BAT 실행기

`launcher.bat`을 더블클릭하면 메뉴가 열린다. 실행 위치와 관계없이 BAT 파일이 있는 폴더를 기준으로 동작하며, 작업 후 창을 유지해 오류를 확인할 수 있다.

| 번호 | 기능 |
| --- | --- |
| 1 | 11개 출처에서 각각 최대 3건 상세 수집, 기존 DB에 반영 |
| 2 | 11개 출처에서 각각 최대 10건 상세 수집, 기존 DB에 반영 |
| 3 | 수집 결과 JSON을 메모장으로 열기 |
| 4 | 인터넷 없이 수집·분류·추출 검증 테스트 실행 |
| 5 | 가상환경이 없으면 생성하고, 고정 버전 의존성 설치 |
| 6 | 저장된 공지 전체를 규칙으로 분류·추출, 인터넷 불필요 |
| 7 | 분류·추출 결과와 원문 근거가 있는 검수 목록을 메모장으로 열기 |
| 0 | 종료 |

GitHub에서 처음 내려받았다면 Python 3.11 이상 설치 후 5번부터 실행한다. 이미 실행 환경이 설정된 폴더라면 바로 1번을 실행하면 된다. 5번 의존성 설치와 1·2번 수집에는 인터넷이 필요하다. 수집과 테스트는 의존성을 자동 설치하지 않으며, 환경이 없으면 5번 실행을 안내한다. 가상환경과 실제 수집 데이터는 저장소에 포함하지 않는다.

직접 확인할 때는 **1번 → 3번 → 원문 URL 열어 비교** 순서로 진행한다. `title`, `body_text`, `images`, `attachments`를 원문과 비교한다. 미수집 글이 남아 있으면 다시 1번을 실행할 때 다른 글을 먼저 가져와 `new`가 나올 수 있다. 같은 글을 다시 요청했고 내용이 같을 때 `unchanged`로 표시된다. `changed`는 이전 저장 내용과 달라 새 버전을 만든 글이다. 본문 텍스트는 HTML 태그 제거 과정에서 줄바꿈이 많을 수 있다. 대회 분류 전이라 일반 안내나 채용 공지도 저장된다.

명령행에서 메뉴 없이 실행할 수도 있다. 이 모드는 자동 검증을 위해 창 대기 없이 종료하며 오류 시 종료 코드 1을 반환한다.

```powershell
# 발견한 목록에서 출처별 최대 50건, 미수집 글 우선
.\launcher.bat run
.\launcher.bat test
.\launcher.bat export
.\launcher.bat setup
.\launcher.bat analyze
```

### Python 명령으로 실행

최초 설치는 Python 3.11 이상으로 아래 순서대로 진행한다. PowerShell에서 myongji-radar 저장소 루트를 기준으로 실행한다. 확인한 의존성 버전은 lock 파일에 기록했다.

```powershell
cd pipeline
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -m collector run --limit 3
```

수집 기본값은 발견한 목록에서 출처별 최대 50건이다. `--limit`은 빠른 시험용으로 상세 요청 상한을 줄이는 옵션이며 범위는 1~50이다. BAT 메뉴 1·2번은 각각 3건·10건의 시험용이고, 메뉴 없는 `launcher.bat run`은 최대 50건을 수집한다. 전체 실행은 몇 분이 걸릴 수 있다.

```powershell
.\.venv\Scripts\python.exe -m collector run --source mju_ctl --limit 5
.\.venv\Scripts\python.exe -m collector export
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

`--config 경로`로 출처 설정을, `--data-dir 경로`로 저장 위치를 바꿀 수 있다. 기본 경로는 실행 위치와 관계없이 이 프로젝트 기준으로 정해진다. 동일 데이터 경로에 여러 실행을 동시에 시작하지 않는다.

### 새 글과 고정 공지 처리

DB의 `(source_id, external_id)`로 저장 여부를 확인한 뒤 다음 순서로 상세 요청한다. 각 그룹 안에서는 RSS·HTML에서 발견한 순서를 유지한다.

1. 아직 저장하지 않은 일반 글
2. 아직 저장하지 않은 고정 공지
3. 저장된 일반 글
4. 저장된 고정 공지

고정 공지 여부는 HTML의 `tr.headline` 또는 번호 칸의 `._artclNotice` 표식으로 구분하며 제목의 ‘공지’라는 단어로 추측하지 않는다. 같은 글이 고정·일반 행에 반복되어도 한 번만 요청하고 고정 표식을 유지한다. RSS는 고정 표식을 제공하지 않으므로 저장 여부와 원래 목록 순서로 처리한다.

이미 저장된 글도 상한에 여유가 있으면 재확인해 변경을 감지한다. 고정 공지를 완전히 제외하지 않으므로 새로 고정한 활동 공지도 수집할 수 있다. 고정 여부는 발견 단계에서만 사용하는 값이며 공지 저장 JSON이나 DB 스키마는 바꾸지 않는다.

한 번에 발견한 글이 50건을 넘으면 다음 실행에서도 목록에 남아 있는 미수집 글을 먼저 처리한다. RSS 최근 목록·HTML 첫 페이지에서 이미 사라진 글이나 장기 중단 기간 전체의 복구까지 보장하지는 않는다. 과거 페이지 탐색은 별도 후속 작업이다.

### 내용 변경과 파서 변경

내용 해시는 제목·본문·이미지 목록·첨부 목록만 사용한다. 이미지 목록의 URL·대체 텍스트(`alt`), 첨부 목록의 URL·파일 이름(`name`)도 해시에 포함한다. 공지 원문 URL·게시 시각·파서 버전과 페이지의 조회 수 등은 내용 버전을 추가하는 기준이 아니다. 본문과 별도로 연결된 이미지·첨부 파일의 실제 바이트 변경은 아직 감지하지 않는다 (#12).

파싱 결과를 바꾸는 파서 수정 시 `collector/models.py`의 `parser_version`도 올린다. 파서 버전이 바뀌면 저장된 HTML을 새 파서로 다시 읽어 현재 공지와 같은 기준으로 비교한다. 이전 파서의 결과와 새 결과가 우연히 같아도 실제 원문 변경을 놓칠 수 있기 때문이다. 내용이 같으면 기존 원문 버전 ID를 유지하면서 파싱 결과와 파서 버전을 갱신한다. 새 파서로 추출한 제목·본문·이미지·첨부가 달라진 경우 새 버전을 만들고, 이전 원문의 파싱 결과도 새 파서 기준으로 갱신한다. 새 파서로 예전 HTML을 읽을 수 없거나 저장 원문이 없으면 해당 글을 오류로 기록하고 기존 이력을 유지한다. 재파싱은 해당 글을 다시 수집할 때 실행되며 모든 과거 버전을 일괄 재처리하지는 않는다. 이전 파서가 놓친 변경은 저장된 이전 HTML을 기준으로만 비교할 수 있다.

파싱 결과가 바뀌어도 원문 버전 ID는 같을 수 있으므로 수집 후 규칙 분석을 다시 실행해야 한다. 분석 저장 (#13)은 버전 ID와 입력 내용 해시를 함께 보존하고, 매일 AI 추출도 두 값이 같아야 캐시를 재사용한다.

기존 DB는 처음 열 때 모든 저장 버전의 해시를 새 기준으로 한 번에 다시 계산한다. 버전 ID·원문 파일·수집 시각은 유지하며 기존 파서 변경 때문에 이미 생긴 중복 버전도 삭제하지 않는다. 변경 전 수집·분석을 종료하고 **`data/` 전체를 비공개 위치에 백업**한 뒤 실행한다. 이전 코드로 DB를 다시 열면 새 해시 기준을 이해하지 못하므로, 이전 코드로 돌아갈 때는 백업을 사용한다. 손상된 저장 결과가 있어 변환에 실패하면 해시 변경을 되돌리고 오류로 종료한다. 사용자 지정 `--data-dir`도 같은 방식으로 백업한다.

#### 과거 버전 비교 규칙 (#13·#16)

이관은 해시만 재계산하며 과거 모든 HTML을 새 파서로 읽지는 않는다. 따라서 과거 버전은 서로 다른 `parser_version`의 결과일 수 있다. 사용하는 쪽은 같은 공지 안에서 다음 규칙을 적용한다.

1. 원문 버전 ID 순으로 보되, **같은 파서 버전으로 해석한 결과끼리만** 내용·추출값을 비교한다. 파서 버전이 다르면 저장 HTML을 같은 파서로 재해석해 비교하거나, 비교 보류로 남긴다. 다른 파서의 해시가 다르다는 사실만으로 마감 변경을 확정하지 않는다.
2. 같은 파서 기준에서 **연속된 동일 내용 해시**는 하나의 내용 상태로 본다. 원래 버전 ID·수집 시각과 근거는 유지하되 중복 행마다 변경 이벤트를 생성하지 않는다. A→B→A처럼 중간에 다른 내용이 있었으면 마지막 A는 별도의 복귀 변경이다.
3. 마감 변경 이력은 동일 기준에서 비교한 **실제 추출 마감값**이 다를 때만 만든다. 제목·첨부 이름 등의 해시 변경만으로 마감 변경이라고 표시하지 않는다. 분석의 재사용도 원문 ID뿐 아니라 파서·파싱 결과·생성기 버전을 확인한다.

이 규칙은 분석 저장(#13)과 후속 병합(#16)이 따르는 계약이다. 분석을 저장하더라도 마감 변경 이력을 자동 확정하지 않는다.

#### 저장 원문 누락·재파싱 실패의 복구

파서가 바뀐 상태에서 이전 원문이 없거나 해석되지 않으면, 그 글의 비교와 저장을 계속 보류하는 것이 의도된 정책이다. 반복 실행만으로 해결되지 않으며 이후 실제 변경도 해당 글에서는 기록되지 않는다. 다른 글은 계속 수집되고 해당 URL·오류는 실행 기록의 `errors`에 남는다. 최신 응답으로 과거 원문 파일을 덮어쓰면 변경 이력의 근거가 바뀌므로 그렇게 복구하지 않는다.

1. 수집·분석을 멈추고 현재 `data/` 전체를 별도 비공개 위치에 백업한다. `--data-dir`을 썼다면 해당 폴더를 사용한다.
2. `notice_versions.raw_path`에 해당하는 **동일한 과거 HTML**이 백업에 있다면 같은 위치에 복원한다. 파일 이름은 원문 SHA-256이므로 백업 파일 내용의 해시와 이름도 대조한다. 원문이 존재하지만 새 파서가 읽지 못하면 그 파일을 입력으로 파서 호환성을 수정하고 파서 버전을 올린다.
3. `launcher.bat test` 후 문제 출처를 `python -m collector run --source 출처ID --limit 50`으로 재실행한다. 해당 글이 수집 상한 밖으로 밀렸다면 목록에서 해당 글을 실제 요청했는지도 실행 기록으로 확인한다. 이후 `launcher.bat analyze`로 분석을 다시 생성한다.
4. 과거 HTML을 되찾거나 해석할 수 없다면 기존 DB의 해당 글은 보류한다. 동작 확인이 꼭 필요하면 빈 **별도 비공개 데이터 폴더**에 `--data-dir`로 새로 수집할 수 있지만 이는 새로운 이력의 시작이다. 기존 DB와 병합하거나 이전의 연속된 변경 이력인 것처럼 취급하지 않는다. 정상 백업으로 전체 복원하거나 수동 재기준점을 지정하는 도구는 별도 후속 검토 대상이다.

## 버전별 분석 저장 (#13)

`collector analyze`와 `extractor daily`는 입력 `notices.json`과 같은 폴더에 운영 DB(`collector.sqlite3`)가 있으면 `analyses`에 결과를 저장한다. 원문 버전 ID·본문 해시를 대조하고, 다른 공지 또는 다른 파싱 결과에 잘못 붙이려 하면 실패한다. DB 없는 JSON 전용 오프라인 시험은 기존처럼 파일만 만들며, 비어 있는 DB를 생성하지 않는다. `extractor eval`은 여러 공지를 묶는 평가 결과라 기존 평가 폴더에만 저장한다.

- 원문 버전, 규칙/AI 생성기 버전, 요청·실제 모델, 프롬프트 버전·지문, 입력 해시, 결과 JSON, 실행 시각을 보관한다. 동일 설정·동일 결과 재저장은 중복을 만들지 않고, 다른 모델·프롬프트·규칙 또는 다른 추출 결과는 함께 남긴다. AI 결과는 현재 캐시를 덮어쓰기 전에 DB에 저장한다.
- 기존 DB v2는 첫 실행 때 v3로 자동 이전한다. 실행 전 `data/` 전체를 비공개로 백업한다. 원문 버전 ID·원문·과거 JSON 분석 이력은 지우지 않는다. 과거 JSON 전체를 자동 역수입하지는 않는다. 새 규칙 실행·새 AI 추출부터 연결된다. 입력 해시가 없는 예전 AI 캐시는 재사용하지 않으며 다음 실행에서 호출 상한 안에서 다시 추출한다.
- 규칙의 내부 `status`는 유지하면서 `contract_status`를 함께 기록한다: `extracted → ai`, `needs_review → needs_check`, `not_stated → missing`. 값의 형태나 참가 허용 여부를 바꾸는 변환은 아니다. 규칙 결과만으로 카드를 공개하지 않는다.
- `collector export`는 원문 변경 시각(`collected_at`)과 마지막 성공 확인 시각(`last_seen_at`)을 함께 내보낸다. 글 내용이 같아 새 버전이 없어도 마지막 확인 시각은 갱신한다. 매일 추출 묶음과 공개 카드의 출처에도 이 값을 전달하며, 알 수 없으면 `null`로 둔다.
- 내부 출처 ID(`mju_ctl`)는 DB·설정 호환을 위해 유지한다. 공개 `boards[].id`·`sources[].board_id`는 `mju-ctl`처럼 하이픈으로 바꾼다. 정규화 결과가 겹치는 설정은 거절한다.

네트워크 없이 확인하려면 먼저 수집한 DB를 백업한 뒤 `python -m collector export`, `python -m collector analyze`를 실행한다. 같은 명령을 다시 실행해도 같은 판·규칙·결과의 분석 행은 늘지 않는다. 저장 결과와 이전 절차는 [데이터 계약](../docs/api-contract.md)의 내부 분석 저장을 따른다.

## AI 추출 (#14)

`extractor/`가 공지를 프롬프트 v0.2로 `claude -p`에 넘긴다. **실행하는 사람의 Claude 로그인으로 돈다** (계정 환경변수가 있으면 시작하지 않는다). 공지는 신뢰할 수 없는 입력이라 도구를 모두 끄고 빈 임시 폴더에서 실행하고, 공지를 보내기 전에 공지 없이 한 번 불러 격리·계정을 확인한다 (`extractor/claude.py` 머리말). 하루 호출 상한은 `data/extract_calls.json`에 센다.

- **모델 비교 (`eval`):** 정답표 대회를 뽑아 채점용 실행 폴더를 만든다. 실행 순서는 `eval/extraction/README.md` "모델 비교 실행 순서".
- **매일 추출 (`daily`):** 규칙 분석이 대회 후보로 본 공지를 뽑아 카드 묶음 파일을 만든다.

```
python -m collector run
python -m collector export          # data/notices.json
python -m collector analyze         # data/analysis.json
python -m extractor daily --model <모델 비교로 정한 모델>   # data/card_bundles.json
```

- 후보: 규칙 분석의 활동 후보(candidate) 중 유형에 대회·해커톤이 있는 공지. 결과 공지는 뺀다 (명단이 AI로 가지 않게). 규칙 분석과 원문의 판이 다르거나 게시일이 없는 공지는 부르기 전에 뺀다 (`[뺌]` 줄).
- **공지 하나 = 카드 하나.** 같은 대회의 공지 묶기(#16) 전까지의 임시 방식이다. 카드 id는 `<출처 id>-<글 번호>`를 영문 소문자·숫자·`-`로 바꾼 것(예: `mju_ctl` + `ctl/792/235972` → `mju-ctl-ctl-792-235972`)이라 날마다 같다.
- 같은 공지 판을 같은 모델·같은 프롬프트(지시·형식·입력 틀·입력 규칙 파일의 지문)로 이미 뽑았으면 다시 부르지 않는다 (`data/extractions/<카드 id>.json`). 새 글·바뀐 글만, 한 번에 `--max-new`(기본 30)개까지.
- **모델·프롬프트만 바꿨을 때는 다시 뽑는 동안 옛 결과로 카드를 남긴다** (원문이 같으므로). **공지가 바뀌면(새 판) 다시 뽑을 때까지 그 카드를 내린다:** 내보내기는 근거 대조에 실패한 항목의 값은 남기므로, 옛 판의 값(지워진 연락처, 바뀌기 전 마감)이 "확인 필요"를 달고 계속 공개될 수 있기 때문이다.
- 같은 판·같은 모델·같은 프롬프트로 3번 실패한 공지는 더 부르지 않는다 (`data/extractions/_failures.json`, `[포기]` 줄). 공지·모델·프롬프트가 바뀌거나 `--force`면 다시 부른다. 부른 것이 모두 실패하면 `[경고]` 줄이 나온다.
- 실행마다 토큰·비용·건수(후보·뽑을 것·포기·뺀 것·취소 공지·옛 결과로 넣은 것·새 판을 기다려 내린 것)를 `data/extractions/_runs.jsonl`에 한 줄 남긴다 (공지 내용 없음).
- 묶음에는 지금 판에서 뽑아 둔 결과가 있는 후보만 넣고, 사람 검수 기록(`statuses`)은 비워 둔다. 이미지·첨부를 AI에 넣지 않으므로 근거 파일 이름(`files`)도 비어 있다. 스키마 강제를 거치지 않은 모델 글은 받지 않는다 (모델 비교 eval의 `meta.json` `totals.text_results`가 0이 아니면 그 모델은 매일 추출에서 실패한다).
- **종료 코드:** 0 처리함 (모델이 형식에 못 맞춘 공지·상한으로 남은 공지는 경고만, 다음 실행이 다시. 매일 공개를 막지 않게), 2 멈춤 (시작하지 못함·확인 호출 실패·격리 어긋남·같은 설정 문제 반복). **멈추면 묶음 파일을 덮어쓰지 않는다** (어제 묶음이 남는다).
- **남은 위험 (#16 전):**
  - 취소 공지는 카드를 만들지 않지만 원래 모집 카드에 반영되지 않는다. 실행 로그의 `[취소 공지]` 줄을 보고 사람이 그 대회의 모집 카드를 확인한다.
  - 연장 공지는 원래 모집 카드와 별도 카드가 된다 (같은 대회가 두 장).
  - 대회 공지인데 규칙 분석의 유형 낱말(`config/rules.toml`의 공모전·경진대회·해커톤 등)이 없는 공지("○○ 챌린지" 등)는 후보가 되지 않는다.

## 추출 결과 검증 (#15)

`verifier/`가 AI 추출 결과를 그대로 믿지 않고 원문과 대조한다. 내보내기 직전에 부르고, 결과는 내보내기가 읽는 `statuses`로 묶음 파일에 넣는다. **앞 단계가 0이 아닌 종료 코드로 끝나면 다음 단계를 돌리지 않는다** (옛 검증 파일로 내보내지 않게).

```
python -m extractor daily --model <모델>   # data/card_bundles.json (위 "AI 추출")
python -m verifier --bundles data/card_bundles.json --notices data/notices.json --out data/card_bundles.verified.json
python -m exporter --bundles data/card_bundles.verified.json --out ../site/data/cards.json
```

- **근거 대조:** 근거가 있는 항목은 flag와 상관없이(확인 필요 항목도 내보내기가 근거를 공개하므로) 근거 문장이 그 공지의 제목·본문(·글자를 뽑은 첨부)에 있는지 본다.
  - 공백·보이지 않는 글자·전각·HTML 이스케이프·물결/줄표/따옴표/가운뎃점 변형만 맞춘다. 말을 바꾼 인용은 실패다.
  - 숫자 사이의 공백은 남기고("10월 2⏎1."이 "10월 21"과 맞지 않게), 숫자로 시작·끝나는 인용은 숫자 경계를 지킨다("3명"이 "13명"에, "3"이 "3.5"에, "100"이 "100,000"에 맞지 않게). 한글 인용은 낱말 첫머리의 부정 글자(불·비·미·무·부) 바로 뒤에서 시작하지 않는다("전공자 대상"이 "비전공자 대상"에, "가능합니다"가 "불가능합니다"에 맞지 않게). 낱말 경계는 정규화 전 원문의 공백으로 판단해서 "참가비 지원 대상"의 "비"(앞 낱말의 끝)는 해당 없다. 붙여 쓴 글("중복지원불가능")은 낱말 경계로 안 보이므로, 뜻이 뒤집히는 흔한 낱말(가능·신청·제출·등록·충족 등)로 시작하는 인용은 부정 글자 바로 뒤면 막는다 (#49). 반대로 한글로 끝나는 인용 바로 뒤에 부정 표현(불가·불필요·금지·제외·제한·없·아니·않·못·안 됨·어렵·곤란·거부·취소 등, 미제출처럼 부정 글자+뒤집히는 낱말)이 오면 맞지 않는다("개인 참가"가 "개인 참가 불가"에). 조사 한 글자(은·는·이·가·도·만·을·를)는 건너뛴다("개인 참가는 불가"). 문장부호로 끝나는 인용이나 뒤가 다음 줄인 경우(줄 단위 목록 "대상: 재학생⏎제외 대상: 휴학생")는 보지 않는다. "불가피"·"불가분"은 부정으로 보지 않는다. 막는 쪽으로 넓게 잡아 "서류 없이 신청"의 "서류"처럼 정상 인용도 근거 대조 실패가 될 수 있다 (안전한 쪽). 조사가 두 글자 이상이거나 문장부호가 끼면("참가, 불가") 보지 못한다. 문장 중간에서 줄을 바꾼 글(첨부에서 뽑은 글 등, "개인 참가⏎불가합니다")도 놓친다. 첨부 글자를 대조하게 되면(#12 뒤) 줄 정보를 쓰지 않는 쪽으로 정한다 (#49).
  - 원문에 있지만 정규화 뒤 4자보다 짧은 인용("전 학년")은 어디에나 들어맞아 `[사람 확인]`으로 둔다. 500자가 넘는 인용은 실패.
  - 근거가 없음, 공지 번호가 틀림, 이미지·첨부 근거의 파일 이름이 그 공지 `files`에 없음, 원문을 못 찾음(같은 URL이 두 번 있어 어느 판인지 모를 때 포함)도 실패.
  - **통과는 "인용이 원문에 있다"는 뜻일 뿐, 값이 그 인용에서 나왔다는 뜻이 아니다.** 값 일치는 교차 검증이 맡는다.
- **사람 확인 근거:** 파일 이름이 맞는 이미지 근거와 글자를 뽑지 않은 첨부 근거는 코드로 대조하지 못한다. 실패로 내리지 않고 실행 로그에 `[사람 확인]`으로 남긴다. 이런 근거는 지금처럼 공개된다 (포스터에만 정보가 있는 공지가 많아 숨기면 근거 없는 카드가 된다. 핵심 항목은 사람 검수 전까지 화면에 "확인 전").
  - 남은 위험: AI가 실제 포스터 파일 이름을 대고 문장을 지어내면 걸러지지 않는다. 신청 방법·혜택·제출물은 "확인 전" 규칙 밖이라 "AI 정리"로 보인다.
  - TODO(jinseojang0903/2026-11-05): 교차 검증(#15 남은 부분)이 붙으면 이미지 근거도 두 모델이 같은 값을 읽었는지로 확인한다. 그 전에 사이트에서 이미지 근거에 "AI가 포스터에서 읽음" 표시를 붙일지 계약과 함께 정한다.
- **상식 검사** (형식 검사는 내보내기가 한다): 게시 연도 ±1년 밖의 날짜, 첫 공지 게시일(한국 날짜)보다 이른 신청 마감, 신청 기간 마감과 "신청" 단계 마감이 다른 경우. 결과·취소 공지는 카드를 만들지 않으므로 보지 않는다. 게시일을 못 읽으면 `[사람 확인]`으로 남긴다.
- **상태는 내려가기만 한다:**
  - 근거 문제: `needs_check` + `evidence_failed`. 내보내기는 그 항목의 근거를 공개하지 않는다. **사람이 검수한 항목도 내린다** (사람이 본 것은 그때의 근거다).
  - 사람 검수(`human_verified`)는 값과 근거가 검수 때와 같을 때만 믿는다. 검수 기록에 `checked_value`와 `checked_evidence`(`verifier.checks.evidence_fingerprint`)를 남긴다. 근거 기록이 없으면 근거를 모두 코드로 대조해 통과했고 문의처가 아닐 때만 믿는다 (사람이 본 적 없는 이미지 근거·연락처 문장이 "검수 완료"로 공개되지 않게).
  - 상식 문제만: `needs_check`. 믿을 수 있는 사람 검수는 그대로 둔다.
  - 이 도구가 쓴 항목에는 `"by": "verifier"`가 붙고, 덮어쓴 사람 검수 기록은 `previous`에 둔다. 다시 검증할 때 지우고(사람 검수는 되살려) 새로 쓴다. 그래서 근거를 고치면 표시가 사라지고, 출력을 다시 입력으로 써도 사람 검수가 없어지지 않는다.
  - 대회명·주관·교내/외부는 카드 최상위 값이라 확인 필요를 표시할 자리가 없다. 근거 대조에 실패하면 내보내기가 경고(종료 코드 1)로 알린다.
- **`auto_verified`는 아직 쓰지 않는다:** 계약상 자동 검증 통과는 다른 모델과의 일치까지 봐야 한다. 교차 검증 모델이 정해질 때까지 통과 항목은 "ai"(확인 전)로 남는다.
- **statuses는 AI 출력에서 오면 안 된다:** 검증기는 기존 `human_verified`를 믿는다. 추출(#14)·병합(#16)은 AI 출력을 `extraction`에만 넣고, `statuses`에는 사람 검수 기록만 넣는다.
- 한 카드에서 예상 못 한 오류가 나면 그 카드의 모든 항목을 근거 문제로 내리고 나머지 카드는 계속 검증한다.
- 로그에는 카드 id(형식이 틀리면 대신 순번)·항목 이름·이유만 남기고 근거 문장·연락처는 남기지 않는다. `--out`이 `site/` 안이면 쓰지 않는다. 종료 코드: 0 검증함, 2 입력을 읽지 못해 출력하지 않음, 3 쓰기 실패.

## 매일 공개 (#19 뒷단)

`publisher/`가 규칙 분석 다음 단계를 순서대로 돌린다. 매일 수집(#31: 수집 → 규칙 분석)이 끝난 뒤에 부른다.

```
python -m publisher --model <모델 비교로 정한 모델>
```

1. 확인: `data/analysis.json`이 지금 `data/notices.json`으로 만든 것인지 (analysis.json의 `input_sha256`). 아니면 분류는 옛 원문, 본문은 새 원문으로 섞이므로 멈춘다.
2. 매일 추출 → `data/card_bundles.json` (위 "AI 추출")
3. 근거 대조 → `data/card_bundles.verified.json` (위 "추출 결과 검증"). 부르기 직전에 1을 한 번 더 확인한다 (추출하는 동안 원문이 바뀌지 않았는지)
4. 내보내기 → `site/data/cards.json` (아래 "cards.json 내보내기")

- **한 단계라도 실패하면 거기서 멈추고 cards.json은 어제 그대로 둔다.** 앞 단계가 0이 아니면 다음을 돌리지 않는다 (옛 묶음을 오늘 원문으로 내보내면 바뀐 공지의 옛 값이 공개될 수 있다). 내보내기의 1(뺀 카드·확인할 일 있음)은 쓴 것으로 보고 끝낸다.
- 단계별 기록: `data/publish_logs/<날짜>.jsonl` (단계·종료 코드·걸린 시간·카드·묶음 수·매일 추출 요약(후보·부른 수·실패·포기·새 판을 기다려 내린 카드). 공지 내용·오류 메시지 없음). 중단(Ctrl+C·예외)도 한 줄 남긴다.
- 종료 코드: 0 cards.json을 새로 씀, 1 새로 썼지만 내보내기 경고가 있음 (로그 확인), 2 멈춤 (cards.json 그대로), 3 `--push`에서 새로 썼지만 올리지 못함. 인자가 틀리면 argparse가 2로 끝낸다.
- `--data-dir`이 `site/` 안이면 시작하지 않는다 (추출 묶음·캐시에는 정리 전 인용·연락처가 있다).
- 매일 추출로 넘기는 옵션: `--max-new`, `--max-calls`, `--timeout`, `--use-env-account`, `--claude`.
- **매일 수집(#31)과 잇는 계약:**
  - 예약 등록·동시 실행 잠금은 #31이 맡는다. **수집 → 규칙 분석 → 이 명령을 같은 잠금 안에서** 부른다 (확인과 사용 사이에 다음 수집이 원문을 바꾸지 않게).
  - 규칙 분석에 성공했을 때만 부른다. 이 명령의 **0과 1은 정상 종료**다 (1을 실패로 다루면 내보내기 경고가 있는 날마다 실패가 된다). 2면 cards.json은 어제 그대로다. `--push`의 3은 카드는 썼지만 올리지 못한 것이므로 **실패로 알린다** (사이트는 어제 그대로).
  - `claude -p`를 쓰므로 실행하는 사람의 Claude 로그인이 있는 PC·계정에서 돈다.
- **운영 전에 정할 것:** 며칠 연속 멈추면 어제 cards.json이 계속 공개된다 (마감이 지난 카드, 학교가 내린 공지 포함). 사이트에 마지막 갱신일 경고, 연속 실패 알림, 특정 카드를 바로 내리는 수동 차단 목록 중 무엇을 둘지 정한다 (#19).
- **배포 (`--push`):** `python -m publisher --model <모델> --push`면 새로 쓴 `site/data/cards.json` **한 파일만** `main`에 커밋·푸시한다 (`publisher/push.py`). 사이트는 Vercel이 `main`의 `site/`를 배포한다 (`site/README.md` "배포").
  - 시작 전에 `main` 브랜치인지 보고 원격 `main`에 맞춘다 (뒤처졌으면 앞으로 감기만). 로컬에만 있는 커밋이 cards.json만 바꿨으면(지난번 못 올린 카드) 버리고 원격에 맞춘다. 카드는 날마다 새로 만들므로 잃는 것이 없다. 다른 파일을 바꾼 커밋이 있으면 아무 단계도 돌리지 않고 2 (사람이 정리. 기록에도 남긴다).
  - 다른 파일이 바뀌었거나 스테이지돼 있어도 담지 않는다. 올라갈 커밋이 **하나라도** cards.json 말고 다른 파일을 바꾸면(main에 남은 개발 커밋, 넣었다 지운 원문 포함) 또는 머지 커밋이 있으면 올리지 않는다. 내용이 그대로면 커밋하지 않는다. force-push는 하지 않는다.
  - 실행 중에 팀이 `main`에 머지해 푸시가 거절되면, 원격 위에 카드를 다시 커밋해 한 번 더 올린다. 그래도 안 되면 3으로 끝내고 로컬 커밋은 남긴다 (다음 실행이 정리해 올린다).
  - 무인 실행이라 git은 자격 증명을 묻지 않고(`GIT_TERMINAL_PROMPT=0`, `GCM_INTERACTIVE=never`) 120초 안에 끝나지 않으면 실패로 본다. 커밋·푸시 훅은 돌리지 않는다 (`--no-verify`). 자격 증명이 만료되면 3이 되므로 실행하는 사람이 git 로그인을 미리 해 둔다.
  - 손으로 고친 cards.json 커밋도 "지난번 못 올린 카드"로 보고 버려진다 (reflog에는 남음). 카드를 급히 내리려면 아래 "수동 차단 목록"을 쓴다.
  - cards.json에는 실행 시각(`generated_at`)이 들어가 카드가 같아도 날마다 커밋 하나와 배포 하나가 생긴다 (사이트의 "마지막 갱신"과 오래된 데이터 안내가 이 시각을 쓴다).
  - 커밋 작성자는 돌리는 사람의 git 설정이다. **Vercel 무료 팀은 비공개 저장소에서 팀 멤버가 아닌 작성자의 커밋을 배포하지 않으므로**, 저장소를 공개로 바꾸기 전에는 팀원 PC에서 올린 카드가 바로 배포되지 않는다 (장진서 커밋이 `main`에 들어갈 때 함께 배포됨).
  - 매일 실행(#31)은 운영 전용 `main` 체크아웃에서 이 명령을 `--push`로 부른다. 개발은 다른 폴더에서 한다.

## cards.json 내보내기 (#17)

`exporter/cards.py`가 AI 추출 결과(프롬프트 v0.2 형식)를 사이트 카드(`docs/api-contract.md` 1절)로 바꾼다. 공개 사이트로 나가는 마지막 관문이다. 매일 실행(#19)이 추출(#14)·검증(#15)·병합(#16) 뒤에 부른다.

```
python -m exporter --bundles data/card_bundles.json --out ../site/data/cards.json
```

**입력 묶음** (`data/card_bundles.json`, 저장소에 올리지 않음. 형식은 `exporter/__main__.py` 머리말과 `CardBundle`):
- `notices`: 그 대회 공지. **AI 입력과 같은 순서**(게시일 이른 것부터, 같은 날이면 출처 id순). 어긋나면 근거 번호를 믿을 수 없어 카드를 뺀다. `files`에 AI에게 넘긴 첨부·이미지 이름을 넣는다 (근거의 파일 이름 대조).
- `statuses` (#15): `{"status", "checked_value", "note", "evidence_failed"}`. 검증 통과는 `checked_value`가 지금 추출 값과 같을 때만 쓴다 (재추출로 값이 바뀌면 `ai`로). 근거를 원문에서 못 찾았으면 `evidence_failed: true` → 근거를 공개하지 않고 원문 확인 필요. 사람이 값을 고쳤으면 고친 값을 `extraction`에 반영해서 넘긴다.
- `is_contest`가 참이 아니거나 `kind`가 결과·취소면 건너뛴다 (오류 아님).

**변환:** flag `missing` → 값 없음, `needs_check`·`conflict`·모르는 값 → 원문 확인 필요, `found` → 검증 결과(없으면 `ai`). 근거가 없으면 자동 검증 통과·검수 완료로 내보내지 않는다. 추출 `warnings`(공지 속 지시문)가 있으면 자동 검증 통과를 쓰지 않는다(사람 검수는 유지). 날짜는 `{date, time}` → `"YYYY-MM-DD HH:MM"`, 시각이 없으면 날짜만이고 채우지 않는다. 날짜가 `start`에만 있는 일정 단계(예선·본선·발표·시상·기타)는 그 날짜를 쓰고 note로 알린다. 신청·출품은 시작일을 마감으로 쓰지 않는다(D-day가 틀려서). 연도를 추정했으면 note에 적는다. 값을 고치거나 일부를 버리면(모르는 태그, 인원 수 형식, 잘린 글 등) 원문 확인 필요로 내리고 이유를 note 앞에 적는다.

**안전 검사:**
- 계약 키만 내보낸다 (대체값·경고 문구·`kind`는 버림).
- 길이: 근거 문장 200자, 값 글자 300자, 항목당 근거 5개, **카드당 근거 합계 1,500자**(같은 문장은 한 번), **카드당 AI note 합계 1,000자**, 학적 용어 10개.
- 링크: 사이트 `safeUrl`과 같은 기준(https, `mju.ac.kr`·`forms.gle`·`docs.google.com` 하위 포함, 계정 정보 없음, 500자 이하, ASCII만·백슬래시 거부, 주소 안에 연락처 없음). 글 속 다른 주소(`bit.ly/…`·`open.kakao.com/…`처럼 `https://` 없이 쓴 것 포함)는 "(주소 생략)". 학교 주소는 http여도 글에는 남긴다.
- 개인 연락처: 모든 글에서 휴대폰 번호·학교 밖 이메일·8자리 이상 숫자열(학번 등)을 가린다. 판정은 전각 숫자·여러 대시·가운뎃점을 정규화한 사본에서 하고(`(010) 1234-5678`, `０１０`, `010–1234`, `hong [at] gmail.com` 등), 문의 전화는 숫자만 모아 휴대폰인지 한 번 더 본다. 문의처 이메일은 `mju.ac.kr`이고 **사람이 검수한 문의처일 때만** 싣는다(학생도 `mju.ac.kr`을 써서 부서 메일과 구분할 수 없음). 글 속 이메일은 학교 주소여도 "(학교 이메일 생략)". **문의처 근거도 사람이 검수한 뒤에만 싣는다**(담당자 이름은 패턴으로 못 가림). "공일공"처럼 패턴으로 못 잡는 표기와 다른 항목의 이름은 #15 사람 검수에서 본다.
- 보이지 않는 글자 제거는 유니코드 범주 기준(제어·서식·서로게이트·사용자 정의·미할당, 한글 채움 문자·이체자 선택자 포함), NFC 정규화, AI 입력의 HTML 이스케이프 되돌림.
- 틀린 마감 변경 이력·메타는 그 항목만 빼고 경고한다 (사이트는 틀린 이력이 있는 카드를 통째로 뺀다).
- 경고로 알리는 것: 대회명·주관·교내/외부의 flag가 found가 아님(계약상 표시할 자리가 없음), 제목에서 연락처·주소를 가림, 이미지·첨부 근거의 파일 이름이 공지 `files`에 없음, 합계 상한으로 뺀 근거·note.
- 출처 공지에 게시일이 없으면(수집기가 날짜를 못 읽은 글) 근거 번호를 믿을 수 없어 그 카드를 뺀다. #14·#16이 묶음을 만들 때 날짜 없는 공지를 먼저 확인한다.

**종료 코드** (#19는 0·1일 때만 배포, 1이면 로그 확인): 0 모두 내보냄, 1 내보냈지만 뺀 카드·확인할 일이 있거나 기존 공개본에서 차단 카드만 제거함, 2 `cards.json`을 바꾸지 않음(묶음 파일·`generated_at` 형식, 카드 0장, 수동 차단 목록을 읽지 못함, 예상 못 한 오류), 3 쓰기 실패(기존 파일 그대로).

**수동 차단 목록 (#65):** 잘못 뽑힌 카드를 급히 내릴 때는 `config/blocked_cards.toml`에 한 칸(`card_id`·`reason`·`since`)을 더하는 PR을 올린다. 형식은 그 파일 머리 주석.
- `card_id`는 사이트 카드 주소 `card.html?id=<여기>`의 값. 운영 PC가 `main`을 받은 다음 실행부터 빠진다 (매일 공개는 이 파일을 기본으로 읽는다).
- **cards.json을 손으로 고치지 않는다:** 카드는 날마다 다시 만들어지고 `--push`가 손으로 고친 카드 커밋을 버린다.
- 목록을 못 읽거나 형식이 하나라도 틀리면 내보내기가 차단 없이 내보내지 않고 2로 멈춘다 (카드는 어제 그대로).
- 뺀 카드는 `[차단] <id>`로만 찍는다. 이유는 저장소 파일에만 있고 기록·cards.json에는 나가지 않는다. 저장소에 올라가므로 이유에 개인정보·공지 원문을 쓰지 않는다.
- 목록에 있는데 이번 묶음에 없는 id는 `[확인]`(종료 코드 1): 오타이거나 공지가 내려가 카드가 사라진 것이다. 사라졌으면 그 칸을 지운다.
- **차단 PR을 머지한 뒤에는 다음 실행 기록과 실제 공개 목록에서 카드가 빠졌는지 확인한다.** 일반 내보내기는 `[차단] <id>`를, 빈 목록 전체 갱신을 막고 기존 목록에서 차단 카드만 정리한 경우 `[확인]`을 기록한다. ID를 잘못 적으면 카드가 계속 공개될 수 있다.
- 남은 카드를 모두 차단해도 기존 공개본의 차단 카드를 제거한다(1). 다른 기존 카드와 원래 기준 시각은 그대로다. 정말 전체가 빈 목록이어야 한다면 운영자가 확인한 뒤 `--allow-empty`를 사용한다.
- 병합 상태에 등록된 그룹은 그룹 ID 또는 구성 공지의 기존 카드 ID를 차단하면 양쪽에 적용한다. 병합 상태에 등록되지 않은 다른 카드의 출처에 같은 공지가 포함된 경우에는 그 카드도 별도로 확인한다.

**사이트 쪽 시험:** `tests/fixtures/exported_cards.json`을 저장소 루트의 `npm test`(`tests/export_contract.test.js`)가 사이트의 형식 검사·판정으로 다시 확인한다. 내보내기 결과를 바꾸면 `UPDATE_FIXTURES=1 python -m unittest tests.test_exporter`로 다시 만든다.

## 결과 확인

- `data/notices.json`: UTF-8 JSON. 제목·본문·원문 URL·이미지·첨부 링크와 버전 ID 확인.
- `data/collector.sqlite3`: 게시글, 원문 버전, 실행 결과 저장.
- `data/raw/`: 변경된 글의 원문 HTML. 네트워크 없이 파서 수정 검증에 활용 가능.
- `data/analysis.json`: 활동 분류, 공지 성격, 일정·조건 언급, 원문 근거·버전·규칙 버전.
- `data/analysis_review.md`: 사람이 읽는 분석 검수 목록. BAT 6번 분석 후 7번으로 열기.
- `data/analysis_history/`: 입력·설정·엔진별 분석 결과 보관.

JSON과 원문은 로컬 확인용이며 그대로 공개하지 않는다. 이미지·첨부 다운로드와 로컬 문서 텍스트 변환은 아래 #12를 따른다. OCR·첨부 AI 입력·HTML 과거 목록 탐색은 아직 연결하지 않았다. 예약 실행은 구현 후 실제 이틀 운영 확인이 남았다 (#31). 목표 11곳을 모두 등록했으며 새 4곳은 각각 5건의 상세 파싱을 확인했다. 수집 성공은 해당 공지가 모집 중이거나 대회라는 의미가 아니다. 규칙의 활동 후보 분류 역시 사람 검수 전이며 개인별 참가 가능 판정은 제공하지 않는다.

직접 분류를 확인하려면 **6번 → 7번** 순서로 실행한다. 새 공지를 가져오려면 그 전에 1번 또는 2번을 실행한다. 자격 필드의 `mentions`는 조건에 등장한 단어로, 허용 대상 목록이 아니다. 예를 들어 휴학생 참가 불가 문장에서 휴학생을 발견한 경우도 포함하므로 근거를 함께 확인한다. `not_stated`와 null은 제한 없음을 의미하지 않는다. 규칙을 고칠 때는 `config/rules.toml`과 `collector/rules.py`를 수정하고 규칙 버전을 올린 뒤 6번으로 재분석한다.

### 날짜·결과 공지 규칙 (#10)

명시된 같은 날짜 범위에서 두 번째 연도를 공유하더라도 잘못된 시각이나 해석하지 못한 시각의 `issue`는 지우지 않는다. `25:00`, `17:60`, `오전/오후`, `정오/자정` 등 읽지 못한 표현을 날짜만 있는 마감으로 확정하지 않고 `needs_review`(`contract_status: needs_check`)로 남긴다. 현재 읽는 시각은 24시간 숫자 표기(`17:30`, `17시`, `17시30분`)다. `3시반`, 지원하지 않는 종료 시각, 시각 범위 역전도 원문 확인 대상이며 근거에 해당 표기를 남긴다. 시각이 없으면 임의로 23:59 같은 값을 채우지 않는다.

일정 라벨이 있어도 콜론이 없거나 날짜를 해석하지 못하면 `not_stated`로 버리지 않는다. 값은 비운 채 라벨 근거와 확인 사유를 남기고, 표의 다음 행사 날짜를 마감으로 추정하지 않는다. 같은 종류의 일정이 여러 개면 해석하지 못한 후보도 보존해 전체를 확인 필요로 둔다. 일정 라벨 자체가 없는 항목만 기존처럼 정보 없음으로 남긴다.

결과 공지 제목의 `모집결과`·`심사결과`·`선발결과`·`최종합격자`·`합격자발표`·`합격발표` 등도 `results`로 분류해 신규 모집으로 취급하지 않는다. 취소·결과 연기 판정 우선순위는 유지한다. 이 규칙은 사람의 참가 자격 확인을 대신하지 않는다.

기존 원문을 다시 수집할 필요 없이 `pipeline`에서 `.\.venv\Scripts\python.exe -m collector export` 후 `.\.venv\Scripts\python.exe -m collector analyze`로 DB에서 내보낸 `notices.json`을 재분석한다. 두 명령 모두 네트워크를 사용하지 않는다. 엔진 파일 해시가 달라져 새 분석 이력이 저장되며 이전 분석은 보존한다. 공개 작업 전에는 재분석한 결과를 사용한다. 회귀 시험은 `.\.venv\Scripts\python.exe -m unittest discover -s tests -p '*rules*.py' -v`로 학교·AI 호출 없이 확인한다. JSON 키·상태값 형식과 추출 프롬프트는 바꾸지 않았다.

정상 시각을 읽은 뒤의 일반 문구에서 다른 시각을 검색하지 않는다. 날짜에 직접 붙은 괄호·마감시간 라벨만 검사하며, ‘신청기간 내’·‘접수기간 이후’ 같은 참조 문구는 새 일정 후보로 만들지 않는다. 모집 제목의 합격자 발표 일정 안내는 실제 결과 발표와 구분한다.

## 현재 출처와 실행 순서

출처 설정은 `config/sources.toml` 하나다. `[defaults]`에서 공통 어댑터·선택자를 지정하고 각 `[[sources]]`에서 다른 값을 덮어쓴다. `priority`가 낮을수록 먼저 실행하며 같은 값은 파일 순서를 따른다. 수집 CLI와 오프라인 점검 스크립트가 같은 로더를 사용한다.

`discovery = "rss"`(기본)는 `rss_url`, `discovery = "html"`은 `list_url`이 필요하다. HTML 출처는 RSS 주소를 생략할 수 있다. 출처 ID 중복, 미등록 어댑터, 빈 선택자·허용 호스트, 잘못된 필드 형식은 HTTP 요청과 DB 생성 전에 오류로 종료한다. 출처별 호스트 접근 제한은 기존 Fetcher가 적용한다.

추가 4곳의 목록 주소·RSS 지원 여부와 표본 결과는 [출처 추가 기록](../docs/collector/출처_추가대상.md)에 있다. 학생활동공지는 이미지 중심 글이 많으며 이번 표본 5건 중 3건이 이미지 전용이었다. 이미지를 읽거나 첨부를 내려받은 결과가 아니라 링크 확보 결과다. 다운로드는 #12에서 진행한다. 본교 게시판과 부서 게시판의 같은 행사도 출처별로 저장하며, 교차 게시의 행사 병합·마감 비교는 #16 범위다.

## 기존 MJU_COLLECTOR 환경에서 이동할 때

`MJU_COLLECTOR/`의 추적 코드를 `pipeline/`으로 옮겼다. 루트의 빈 `collector/`와 중복 설정 `boards.yaml`은 제거했고 설계·검증 문서 3개는 `docs/collector/`로 이동했다. 공지 ID, 저장 JSON, DB 스키마와 수집 기본값은 이번 정리에서 바꾸지 않았다.

1. 실행 중인 수집·분석 작업을 종료하고 기존 `MJU_COLLECTOR/data/`를 비공개 위치에 백업한다.
2. 아직 `pipeline/data/`가 없다면 기존 `data/`를 그 위치로 옮긴다. 두 경로에 모두 데이터가 있다면 덮어쓰지 말고 사용할 DB를 먼저 정한다. Git은 무시된 로컬 데이터를 자동으로 옮겨 주지 않는다.
3. 기존 `.venv`를 복사·이동하지 않고 위 설치 절차로 `pipeline/.venv`를 새로 만든다. 가상환경에는 이전 절대 경로가 남을 수 있다.
4. 바로가기·작업 스케줄러·실행 스크립트의 경로를 새 위치로 바꾼다. 예약 실행은 위의 #31 운영 안내에 따라 scripts/run_daily_collect.ps1을 사용한다.
5. 새 위치에서 `launcher.bat test`, `launcher.bat export`를 실행해 테스트와 기존 DB 내보내기를 확인한다. 기존 데이터가 있다면 이전 건수와 비교한다.

기본 저장 위치는 `pipeline/data/`이며 `.gitignore`로 제외한다. `--data-dir`로 다른 비공개 경로를 지정할 수도 있다. 원문·DB·분석 결과는 저장소나 공개 사이트에 올리지 않는다.

## 검토된 공지 병합과 마감 이력 (#16)

제목 유사도로 병합하지 않는다. `config/contest_groups.toml`의 같은 연도·회차·참가 범위를 확인한 공지 식별자만 묶는다. 정답표의 출처 목록에 근거한 AI 리터러시·역사 영상·WHAT-SSUP·우수리포트·Speak Up 5개 그룹을 초기 등록했다. 캠퍼스별로 별개인 EVC는 묶지 않았다. 기본 공개 흐름의 병합 옵션은 꺼져 있으며 먼저 원문 수집/추출 누락과 그룹 설정을 검토한다.

```powershell
# pipeline에서. 수집/추출이 끝난 로컬 입력만 사용하며 merger 자체는 AI·학교를 호출하지 않는다.
.\.venv\Scripts\python.exe -m merger
# 병합 이후에도 근거를 다시 검증한 뒤 공개 JSON으로 변환한다.
.\.venv\Scripts\python.exe -m verifier --bundles data/card_bundles.merged.json --notices data/notices.json --out data/card_bundles.verified.json
.\.venv\Scripts\python.exe -m exporter --bundles data/card_bundles.verified.json
# 실제 운영 모델을 #9로 정한 뒤 선택적으로 연결한다. 아래 명령은 AI를 호출할 수 있다.
.\.venv\Scripts\python.exe -m publisher --model <선정 모델> --merge-contests
```

- 미등록 공지는 기존 공지별 ID를 유지하고, 등록 그룹은 설정의 고정 ID를 쓴다. 최초 활성화로 URL의 카드 ID가 달라진다. 공유 링크 별칭은 없으므로 배포 전 점검한다. 기존 구성 공지의 차단 ID 또는 새 그룹 ID가 차단 목록에 있으면 전체 그룹을 제외해 차단을 우회하지 않는다.
- 현재 원문 판·입력 해시와 맞지 않는 묶음, 잘못된 그룹·이전 상태는 중단하고 기존 파일을 유지한다. 구성 공지의 수집/추출 누락과 결과 연기·종료가 불확실한 공지는 그룹을 보류(종료1)한다. 최종 결과 또는 대회 자체 취소가 원문에 명확하고 다른 구성 공지보다 늦은 경우에만 종료 상태를 저장한다. 예선 결과나 결과 발표 예정은 최종 종료가 아니다. 보류된 원문이 다음 버전으로 확인되기 전에는 재추출만으로 보류를 해제하지 않는다. 종료 상태도 다음 실행에 유지하므로 잘못된 판정은 운영자의 검토·상태 이관이 필요하다. 결과/연기 공지를 묶기 위해 명단을 AI에 추가로 보내지 않는다.
- 병합은 자격 조건의 합집합·교집합을 만들어 참가 가능을 확정하지 않는다. 상충값은 `conflict`, 최신 공지의 누락값을 이전 값으로 보완할 때는 `needs_check`로 남기며 사람 검수 상태를 승계하지 않는다. 화면에 별도 상태 표시가 없는 제목·주관·교내외 구분의 추출값이 충돌하거나 인용이 원문에 없거나 대조 불가면 그룹 전체를 보류한다. 인용이 존재해도 값과 원문의 의미가 일치하는지까지 확인하지 못한다. 공지 정렬에 맞게 근거 번호를 다시 매기고 기존 검증기를 거친다.
- 마감 이력은 근거가 원문과 대조되고 인용문 자체가 명확한 신청 종료 날짜·시각을 뒷받침하는 `found` 추출값과 실제 원문 버전 차이를 사용한다. 작품 제출 마감, 게시일, 시작일과 결과일 등을 신청 마감으로 단정하지 않는다. 최초 복수 공지는 첫 판·다른 게시일·명시 연장/변경·같은 모델/프롬프트가 필요하다. 같은 URL의 연속된 다음 판도 비교한다. 원문 그대로의 재추출 차이, 모델/프롬프트 차이, 시각/연도 추정, 중간 판 미확인이나 관측 순서 불명확은 이력을 확정하지 않는다. 동일 마감 재실행은 중복 이력을 만들지 않고 A→B→A는 실제 판 변화일 때 복귀로 남긴다.
- `checked_at`은 병합기가 차이를 관측한 한국 날짜이며 실제 변경 공지 게시일을 추정한 것이 아니다. 이력은 공식 일정 검수 완료를 의미하지 않는다. 게시일보다 이른 옛 마감은 이력 후보로 비교할 수 있지만, 원문 대조가 안 된 포스터·첨부 값은 이력에서 제외한다. #14의 이미지/첨부 근거 연결이 끝나기 전에는 일부 실제 이력이 보류될 수 있다.
- `data/card_bundles.merged.json`에 묶음과 비공개 `merge_state`를 함께 원자적으로 저장한다. 이전 이력의 신뢰도가 불명확해지면 이력 원본은 비공개로 보존하고 공개 이력을 숨긴다. `merge_report.history_review_ids`를 운영자가 확인해야 하며 이후 버전이 와도 자동 복구하지 않는다. 운영 전 data 전체를 백업하고 동시 실행하지 않는다. CLI와 `publisher --merge-contests`는 공통 CollectorLock을 잡는다. 이미 같은 잠금을 가진 자동 실행기에서 부를 때는 publisher의 `lock_held=True` 호출 계약을 지킨다.
- 기존 그룹에서 구성 공지를 빼거나 그룹 ID를 바꾸거나 다른 행사에 재사용하면 중단한다. 잘못된 병합을 분리/이전하려면 중지·전체 백업 후 ID와 이전 상태 및 차단 목록의 수동 이관을 검토한다. 자동 분리·이력 역수입은 하지 않는다. 병합 상태가 생긴 데이터 폴더에서는 병합 옵션 없는 publisher와 상태가 다른 묶음의 exporter 사용을 차단한다. publisher 출력은 비공개 data 폴더 밖에 둔다. 독립 테스트는 별도 data 폴더에서 한다.
- 카드가 모두 내려가 0장이 되면 기본적으로 종료 코드 2로 멈추어 어제 cards.json을 유지한다. **정말 빈 목록이어야 하는지 확인한 운영자만** `publisher --merge-contests --allow-empty` 또는 exporter의 `--allow-empty`를 사용한다. 보류된 그룹이 있어 결과가 빈 경우에는 이 옵션도 거부한다. 빈 목록 전체 갱신이 불가능할 때 기존 공개본에 수동 차단된 그룹 또는 그 구성 공지가 있다면 그 카드만 원자적으로 제거하고 다른 카드·기준 시각은 유지하며 종료 코드 1을 반환한다. 기존 공개 내용이 남는 경우 운영자가 즉시 검토해야 한다.

과거 버전 수를 모르는 기존 JSON은 초기 이력 생성에 쓰지 않는다. 새 코드로 `collector export` → `collector analyze` → `extractor daily --model <선정 모델>` 순서로 입력을 다시 만들면 버전/해시 provenance가 붙는다. 동일 모델·프롬프트의 현재 캐시는 재사용하며 merger가 AI를 추가 호출하지는 않는다. 사전 검토는 `.\.venv\Scripts\python.exe -m unittest discover -s tests -p '*merger*.py' -v`로 한다. 역사 영상의 조사표 URL·9/30→10/23 값을 사용한 fixture와 AI 리터러시 동일 URL의 **합성** 버전 변경을 구분해 검증하며 실제 AI 리터러시 신청 마감 변경을 확인했다고 주장하지 않는다.

## 이미지·첨부 저장 (#12)

기존 `collector run`과 BAT 수집 메뉴에서 이미지·첨부도 함께 내려받는다. 먼저 가상환경에서 `python -m pip install -r requirements.lock.txt`로 PDF·HWP 변환 의존성을 설치한다.

```powershell
# 저장소 루트가 아닌 pipeline 폴더에서 실행. 시험 데이터도 비공개 data 아래에 둔다.
.\.venv\Scripts\python.exe -m collector run --source mju_general --limit 1 --data-dir data/asset-smoke
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_assets.py -v
```

`data/asset-smoke/notices.json`에서 `images`·`attachments`를 확인한다. `local_path` 파일은 지정한 data 폴더를 기준으로 열고, `text_status: extracted`이면 `text_path`를 열어 원문과 비교한다. `mju_general`이 설정에 없는 경우 `config/sources.toml`의 ID를 사용한다. 같은 URL의 파일 바이트가 바뀌면 `changed`, 같으면 `unchanged`다. 처음 파일 해시를 추가하는 기존 공지는 한 번 `changed`가 된다.

- 허용 호스트와 리다이렉트 검증·호스트별 간격은 기존 `Fetcher.get`을 그대로 사용한다. 파일당 5MiB, 공지당 20개·총 20MiB 상한이다. 실행 내 중복 URL은 한 번 요청하며 다음 실행에는 다시 내려받아 변경을 확인한다.
- 자산 URL 요청 1,000회·성공 응답 바이트 200MiB·수집 실행 시작 후 20분을 기준으로 새 첨부 처리를 중단한다. 시간에는 RSS/본문을 기다린 시간도 포함된다. 바이트 상한은 마지막 응답을 읽은 뒤 알 수 있으므로 한 응답만큼 더 받을 수 있고, 진행 중인 요청/변환을 즉시 취소하는 전체 시간 제한은 아니다. 한 URL의 Fetcher 내부 재시도는 URL 요청 횟수와 별개다. 상한 이후 첨부는 `skipped` 경고이며 본문 수집은 계속한다.
- 파일명이나 URL 경로를 로컬 경로에 쓰지 않는다. 원본은 `assets/<sha256>.bin`, 텍스트는 `asset_text/<sha256>.txt`에 원자적으로 저장한다. 파일 확장자를 믿지 않고 바이트 헤더로 변환 형식을 판별한다.
- PDF(텍스트 문서), HWP 5(일반 본문), HWPX(본문 XML)를 지원한다. 변환은 빈 임시 폴더의 별도 Python 프로세스에서 15초 제한으로 실행한다. PDF 100쪽, HWP/HWPX 본문 확장 10MiB, 출력 20만 글자 상한이다. Windows에서 변환 프로세스의 메모리 상한은 별도로 강제하지 않는다.
- 이미지 OCR, 스캔 PDF, 암호·배포용 HWP, 구형 HWP, 표·수식의 레이아웃 복원은 지원하지 않는다. `needs_review`와 사유를 남기므로 정보가 없다고 단정하면 안 된다. 추출 텍스트도 원문 검수 전이다.
- 주소 정책 위반·용량/개수/실행 예산 초과·HTTP 4xx(408/425/429 제외)는 `skipped`와 `warnings`로 보고하며 이것만 있으면 종료 코드 0이다. 타임아웃·연결/서버 오류·429·로컬 저장 오류는 `failed`와 `errors`, 코드 1이다. 본문/다른 첨부는 계속 저장하며 이전 파일이 있더라도 `skipped`/`failed`이면 현재 확인이 되지 않은 상태다.
- 일일 실행은 완료된 이번 수집에서 한 건 이상 저장했으면 코드 1이어도 규칙 분석한다. 경고만 있으면 정상 완료, 실제 수집 오류가 있으면 분석 성공 후에도 `partial_failure`·최종 코드 1이다. 전체 실패·미완료 실행이면 분석하지 않고 이전 파일을 유지한다. publisher 자동 연결은 아직 없으며 연결 시 실제 오류가 있는 실행은 공개하지 않는 계약을 유지한다. 당일 재시도는 하지 않고 다음 날 기존 일일 1회 정책으로 다시 확인한다.
- 같은 해시의 비어 있지 않은 변환 텍스트가 있으면 변환을 생략한다. 변환 실패는 다운로드 성공 바이트를 보존한 채 `text_status: needs_review`와 안전한 오류 종류/고정 코드만 남긴다. 변환기를 바꿔 다시 뽑으려면 중지·백업 후 `asset_text`의 해당 텍스트 캐시를 지우고 다음 수집에서 재생성한다. 파일 재다운로드를 없애면 같은 URL의 파일 교체를 놓칠 수 있어 매일 파일 확인은 유지한다. HTTP 조건부 요청은 후속 검토다.
- 첫 수집에서 기존 이미지·첨부 공지에 파일 해시가 추가되면 새 원문 버전이 된다. 매일 AI 추출은 새 버전 재추출 전까지 해당 카드를 내려두므로 `--max-new` 기본 30건씩 복구될 수 있다. 아직 실제 추출을 하지 않았다면 기존 공개 카드에 미치는 영향은 없다.
- 내려받은 사본에는 Mark-of-the-Web을 추가하지 않는다. 문서는 원문 사이트에서 확인하거나 샌드박스에서만 연다.
- 파일·텍스트·변환 임시 파일은 모두 data 아래이며 Git에 올리지 않는다. 이 변경은 AI 입력·첨부 근거 대조에 아직 연결하지 않는다. 수집 뒤 `notices.json`으로 로컬 확인하는 단계다. 기존 AI는 본문만 사용하므로 첨부 전용 공지는 계속 확인 필요다.

변환 구현 참고: [pypdf 텍스트 추출과 한계](https://pypdf.readthedocs.io/en/stable/user/extract-text.html), [olefile API](https://olefile.readthedocs.io/en/stable/olefile.html), [한컴 HWP 5 공개 명세](https://cdn.hancom.com/link/docs/%ED%95%9C%EA%B8%80%EB%AC%B8%EC%84%9C%ED%8C%8C%EC%9D%BC%ED%98%95%EC%8B%9D_5.0_revision1.2.pdf).

## 항목 단위 오류 격리와 수집 보안 (#11)

- RSS·HTML 목록의 날짜/링크가 잘못된 항목만 건너뛰고 같은 목록의 정상 글은 계속 저장한다. 항목 URL과 고정 오류 코드(`invalid_rss_item`, `invalid_html_item`)를 `runs.result_json`의 출처별 `errors`에 남긴다. 오류가 있으면 종료1이며 일일 실행은 저장한 글이 있으면 분석 후 `partial_failure`로 보고한다. XML 전체가 깨졌거나 목록 구조가 맞지 않으면 출처 단위 실패는 유지한다. RSS 미지원 안내만 있는 목록도 오류0으로 성공 처리하지 않는다.
- 시작 시 `allowed_hosts`는 소문자 DNS 형식의 정확한 `.mju.ac.kr` 하위 호스트만 허용한다. 와일드카드·IP·외부 도메인·접미사 위장·학교 최상위 `mju.ac.kr`는 허용하지 않는다. RSS/목록 URL도 인증정보 없는 HTTPS·허용 호스트·443이어야 하며 잘못된 설정은 DB 생성·네트워크 전에 거부한다. 단위 시험도 실제 요청 대신 가짜 학교 호스트 응답을 사용한다.
- Fetcher의 단일 `get`은 기본60초 전체 예산을 갖는다. 프로세스 생성·호스트 대기·재시도·리다이렉트·본문과 IPC 수신이 같은 예산을 사용한다. 별도 HTTP 프로세스를 부모가 감독해 DNS/응답 수신이 멈춰도 종료하며 프로세스/통신 스레드 정리에 최대 약1.5초가 추가될 수 있다. 429는 `Retry-After`가 숫자 0~30초인 경우에만 재시도하고, 그 밖의 값은 즉시 HTTP 오류로 실패한다. 500/502/503/504의 숫자·HTTP-date 재시도 대기는 최대30초다. 같은 호스트 간격1초·리다이렉트마다 HTTPS/허용 호스트 재검사·5MiB 상한은 유지한다.
- 수집 `run` 전체는 기본20분의 공유 요청 예산을 사용한다(`--run-timeout` 초). RSS·상세·이미지·첨부 모두 남은 시간 안에서 요청하며 만료 뒤 새 HTTP 작업자를 만들지 않는다. 이미 저장한 글은 보존하고 이번 실행 오류를 기록한다. 파싱·저장·문서 변환은 단계 경계에서 만료를 확인하므로 진행 중인 문서 변환(기존 최대15초)과 정리 시간은 추가될 수 있다. 운영 PC의 실제 일일 수집 시간과 창 깜빡임은 별도 실측이 필요하다.
- 압축 응답을 해제하는 과정의 메모리 보호를 위해 일반 설치에도 `urllib3>=2.6.0,<3`을 요구한다. 잠금 버전은 `2.8.0`이며 운영 가상환경도 같은 버전을 확인했다.
- 요청마다 새 HTTP 세션을 만들기 때문에 호출 간 연결 풀은 재사용하지 않는다. 익명 쿠키의 domain/path/secure/expiry는 부모와 작업자 사이에서 보존하며 로그·DB에 기록하지 않는다. 부모 Session의 개인 auth/adapters/proxies 사용자확장은 지원 범위가 아니다. 기본 CLI/BAT는 그대로 실행하고, 사용자 Python 스크립트에서 직접 호출한다면 `if __name__ == '__main__':` 안에서 실행해야 한다(spawn 방식).
- 작업자 메타데이터는64KiB 상한이다. 아주 많은 쿠키가 누적되어 이 상한을 넘으면 IPC 오류로 해당 요청을 실패 처리한다.
- 제목·본문·이미지 alt·첨부 이름에서 ANSI/OSC/C1·방향 제어 등을 제거하고 본문 줄바꿈/탭은 유지한다. CLI의 외부 문자열 출력도 정제한다. 원문 HTML 바이트는 바꾸지 않고 비공개 raw에 보존한다. 제어문자만 반복한 입력이 정제 정규식을 느리게 만드는 경우도 회귀 시험으로 차단했다.
- 정제 결과 변경을 반영해 파서는 `k2web-v1.1`이다. 다음 수집에서 기존 raw를 현재 파서로 다시 읽어 비교하므로 정제만 달라졌다고 새 원문 판을 만들지 않는다. 이후 `collector export` → `collector analyze`로 갱신된 payload를 분석한다. 파서가 바뀌어도 같은 원문 판의 입력 해시가 달라질 수 있으며 #13의 분석 이력·AI 캐시는 이를 구분한다.
- 새 raw HTML은 data 안의 임시 파일에 완전히 쓴 다음 원자적으로 교체한다. 교체에 실패하면 DB 버전을 추가하지 않고 임시 파일을 정리한다. 기존 원문을 임의로 덮어써 복구하지 않는다. BAT는 `NoDefaultCurrentDirectoryInExePath=1`로 현재 폴더의 실행 파일이 기본 검색에 끼어드는 것을 막는다.

학교·AI 호출 없이 `pipeline`에서 `.\.venv\Scripts\python.exe -m unittest discover -s tests -q`로 검증한다. 지연 작업자와 미완료 IPC는 짧은 가짜 예산으로 시험하므로 실제60초를 기다리지 않는다. 운영 PC의 실제 예약 실행·학교 네트워크 성공을 이 시험으로 확인한 것은 아니다.
