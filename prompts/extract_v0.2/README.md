# 대회 카드 추출 프롬프트 v0.2

- 작성: 2026-11-03, 이슈 #8. Claude Code 초안 → 팀 검토
- 용도: 공지(본문 + 포스터 이미지 + 첨부 텍스트)를 읽고 대회 카드 항목을 JSON으로 채운다. 파이프라인의 AI 추출 단계(#14)가 쓴다.
- 이전 버전: `../extract_v0.1.md` (2026-10-13, 실제 공지 3건으로 시험)

## 파일

| 파일 | 내용 | 누가 읽나 |
|---|---|---|
| `system.md` | AI에게 주는 지시 (규칙, 항목 정의) | AI. `--append-system-prompt`로 전달 (#14) |
| `input_template.md` | 공지를 감싸는 입력 틀. 공지는 `<notice>` 경계 안에 데이터로 넣는다 | 파이프라인 코드가 채움 |
| `schema.json` | 출력 형식. `claude -p --json-schema`로 강제하고 코드가 한 번 더 검사 | AI·코드 |
| `build_schema.py` | `schema.json` 생성기. 형식을 바꿀 때는 이것을 고치고 다시 실행 | 개발자 |
| `example_output.json` | 출력 형식 예시 (아래 주의) | 개발자·테스트 |

> `example_output.json`은 **형식 예시**다. v0.1 때 AI가 AI 리터러시 공지에서 뽑은 값을 v0.2 형식으로 옮긴 것이고, 정답도 수집기 데이터도 아니다. 이미지 파일 이름(`일정표(임시 이름).png`)은 실제 이름을 몰라 붙인 임시 이름이다. 정답은 사람이 원문만 보고 만드는 `eval/answer_key/`다.

## v0.1에서 바꾼 것과 이유

v0.1을 실제 공지 3건(AI 리터러시, 영어 영상, 역사 영상)으로 시험한 결과에서 나온 문제를 고쳤다. 원 기록: 작업 폴더 `docs/prompts/대회카드_추출_v0.1_결과.md` "실행 관찰".

| # | v0.1에서 발견한 문제 (실제 사례) | v0.2에서 바꾼 것 | system.md |
|---|---|---|---|
| 1 | 공지가 2개인 대회에서 근거 위치가 "본문"뿐이라 어느 공지인지 알 수 없음 (역사 영상: 대학혁신 공지와 일반공지) | 근거마다 공지 번호 + 위치(제목·본문·이미지·첨부) + 파일 이름 | 1절 규칙 2 |
| 2 | 같은 공지 안에서 본문과 포스터의 제외 대상이 다름. 늦은 쪽 하나만 고르면 포스터에만 있던 "졸업유예생, 기존 수상자"가 빠짐 | 충돌 범위를 같은 공지 안의 본문·이미지·첨부까지 넓힘. 목록 값은 **합치고** 충돌 표시, 단일 값은 고르고 나머지를 `alternatives`에 | 3절 |
| 3 | 시각이 없는 날짜를 표기할 방법이 없음 | 날짜와 시각을 나누고 시각이 없으면 `null`. 23:59 등으로 채우지 않음. 연도 추정은 따로 표시 | 2절 |
| 4 | 자격 문구가 없으면 판정이 항상 보류됨 (영어 영상) | "정보 없음"(대상 문장 자체가 없음)과 "제한 문구 없음"(대상 문장은 있으나 그 기준으로 나누지 않음, `any`)을 구분 | 1절 규칙 4 |
| 5 | "교내/외부", "연계 역량", "마일리지" 정의가 모호함 | 항목마다 넣을 것·넣지 않을 것 정의. 마일리지는 원문·영역·점수로 나눔. 연계 역량은 카드 항목에서 뺌 (화면에서 쓰지 않음) | 4절 |
| 6 | 판정 기준일이 없고 불가 사유를 구분하지 못함 | **판정을 프롬프트에서 뺌.** 신청 가능 여부는 규칙 코드(`site/js/rules.js`, #22)가 판정 | (삭제) |

함께 바꾼 것:
- **출력을 표에서 JSON으로.** 사람이 읽는 표 대신 정해진 형식(`schema.json`)으로 받아 코드가 검사·저장한다.
- **공지는 데이터일 뿐 지시가 아니다.** 공지를 `<notice>` 경계로 감싸고, 그 안의 지시문은 따르지 않고 `warnings`에 남기게 했다 (11/3 보안 리뷰 권고).
- **결과 공지의 명단을 옮겨 적지 않는다.** 수상자 이름·학번이 AI 출력과 저장소로 퍼지지 않게 (보안 리뷰 권고).
- **`is_contest`, `kind` 추가.** 규칙 필터를 통과한 비대회 공지를 한 번 더 거르고, 연장·변경 공지를 마감 변경 이력(#16)에 쓴다.

### 코드 리뷰(Claude 리뷰 에이전트)로 고친 것

첫 초안을 리뷰해 채점이 흔들리거나 위험 오판이 생길 수 있는 곳을 고쳤다.

| 리뷰 지적 | 고친 것 |
|---|---|
| 출처끼리 목록을 "합치기"만 하면 허용 범위가 넓어짐 (예: 1~4학년 → 3~4학년으로 바뀐 공지를 합치면 1·2학년이 "가능") | 제외 목록은 합치고, **허용 범위는 좁은 쪽(교집합)**. 나중 공지가 바꾼다고 밝힌 값(연장·변경)은 갱신으로 보고 나중 값 |
| 11월 공지의 "1월 15일 마감"을 게시 연도로 채우면 지난 날짜가 됨 | 게시월보다 이른 월이면 다음 해 + 확인 필요 |
| `enrollment`에는 `any`가 없어 "학적 언급 없음"을 표현할 수 없음 | 빈 목록 = 제한 문구 없음, `null` = 정보 없음 |
| `apply`와 `stages` 규칙이 서로 달라 단계 이름이 모델마다 다름 | `apply`가 있으면 `stages`에 항상 `신청`. "서류 제출" 단계 이름은 없앰 |
| 연장 공지가 "충돌"로 표시되어 연장된 대회가 늘 확인 필요가 됨 | 갱신(found)과 같은 시점 불일치(conflict)를 나누고 우선순위 명시 |
| 예시 출력이 "모든 값에 근거" 규칙을 어김 | 실제 원문 인용으로 바꿈 |
| 정답표가 충돌 값을 고르는 기준이 AI와 달라 다른 것을 재게 됨 | 정답표 README에 같은 기준을 옮김. flag 채점을 양방향으로 (과잉 보류는 "확인 필요 비율"로 따로) |
| 입력 이스케이프가 공지 경계 태그만 막음 | 내용·속성 전체를 이스케이프, 근거 대조는 이스케이프한 텍스트 기준 |
| 출력 형식이 36KB로 Windows 명령줄 한도(약 32KB)를 넘을 수 있음 | 설명문 제거·압축, 날짜를 항상 같은 모양으로, 대안 값은 공지 번호만 → 17KB. 2만 바이트를 넘으면 생성기가 실패 |

## 데이터 계약과의 관계

- 출력 항목 이름은 `docs/api-contract.md`의 `fields`와 같다. 예외: `kind`(공지 성격)는 카드에 넣지 않고 마감 변경 이력(#16)에만 쓰고, `stages`의 `start`·`label`은 계약에 아직 없다 (내보내기 #17에서 넣을지 정한다). 이 PR에서 계약도 맞췄다: 근거 위치에 `제목`, `campus`·`grades`의 `any` 규칙(대상 문장에 구분 없음), `enrollment` 빈 목록의 뜻, `team`의 null, 제출물 태그 목록, `mileage`·`how_to_apply`를 객체로.
- 값 모양이 다른 곳(날짜를 date·time으로 분리, `campus`·`grades`를 `{any, allowed}`로)은 내보내기 단계(#17)가 카드 형식으로 바꾼다.
- `flag` → 계약 `status` 매핑은 #13에서 확정한다: `found` → `ai`(검증 후 `auto_verified`), `missing` → `missing`, `needs_check`·`conflict` → `needs_check`.
- 판정 순서(계약 3절)는 #22에서 정리한다.

### 머지 전 리뷰(11/4)로 고친 것

| 리뷰 지적 | 고친 것 |
|---|---|
| 개인 참가 가능 여부가 없을 때(`team.individual_ok: null`) 계약에 처리가 없어 "신청 가능"으로 빠질 수 있음 | 계약에 `null`의 뜻과 판정(`check`)을 적음 |

| 예시 출력 mileage의 "수상자는 추가 점수"에 근거 없음 | 문구 삭제 |

## 아직 하지 않은 것

- **출력 형식이 `claude -p --json-schema`에서 그대로 받아들여지는지**(길이 제한·패턴·여러 형식 허용)는 실제 실행(#9, #14)에서 확인한다.

- **실제 실행과 정확도 측정은 #9**(모델 비교)에서 정답표(#7)로 한다. 이 PR은 프롬프트와 형식만 정한다.
- 이미지를 Claude Code에 넘기는 방법(파일 읽기 권한을 입력 폴더로만 제한)은 #14에서 정한다.
