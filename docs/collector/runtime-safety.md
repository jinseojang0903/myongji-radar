# 수동·예약 운영 실행 계약 (#149)

## 실행 순서와 근거

예약과 수동 일일 실행은 기존 `scripts/run_daily_collect.ps1`을 사용한다. Python의 `collector.daily --publish-config ...` 진입점이 `runtime.launch`를 호출해 다음 순서로 실행한다.

1. 같은 `data/collector.lock`의 OS 잠금을 얻는다.
2. 기존 `publisher.push.prepare`로 운영 main을 동기화한다.
3. 같은 가상환경의 새 Python 프로세스에서 수집 → 분석 → 활성화된 공개 단계를 실행한다.
4. 부모는 자식 종료까지 잠금을 유지하고 실제 종료 코드를 반환한다.

`publisher --push`도 같은 실행기를 사용한다. 동기화 뒤 새 프로세스를 만드는 이유는 이미 import한 추출·검증·내보내기 함수가 파일만 바꿔서는 갱신되지 않기 때문이다. 여러 모듈을 다시 읽는 방식은 기존 함수 참조와 전역 상태가 남을 수 있다. 새 프로세스 하나로 import 경계를 정하며 별도 서버나 예약 도구는 추가하지 않는다. 경로 인자는 호출 위치에서 절대 경로로 확정해 자식의 작업 폴더가 달라도 같은 데이터를 사용한다.

수동 `publisher`에서 `--push`를 생략하면 Git 동기화 없이 현재 체크아웃으로 실행하지만 같은 잠금을 얻는다. `collector.daily`의 공개 설정을 생략한 수집·분석 개발 경로도 기존처럼 현재 코드로 실행한다. `--dry-run`, `--recover-state`, 인자 도움말은 코드 갱신이나 작업자 실행을 하지 않는다. 운영 동기화는 `enabled=false` 또는 `push=false`여도 `--publish-config`가 있으면 수집 시작 전에 수행한다. 따라서 운영 경로는 읽기 전용 Git 네트워크 연결이 필요하며, 준비 실패 시 수집하지 않는다.

일일 작업자가 publisher를 직접 부를 때는 `lock_held=True, synchronized=True`를 넘긴다. 이는 외부 CLI 옵션이 아닌 내부 함수 계약이다. 잠금·갱신을 이중 수행하지 않고 수집부터 공개까지 같은 잠금을 유지한다. 작업자 실행 중에는 개발 브랜치를 바꾸거나 코드를 수동 수정하지 않는다. 마지막 카드 푸시의 원격 경합 처리는 기존대로 유지하며 단계 처리가 끝난 뒤에만 실행한다.

## 잠금과 종료 코드

잠금 충돌은 AI 호출·캐시·카드·Git 작업보다 먼저 막는다. 수동 publisher는 2, 일일 CLI는 중복 실행 건너뜀 0이다. 잠금 파일은 삭제하지 않는다. 상태 파일은 어느 쪽도 덮어쓰지 않는다.

같은 날 이미 시도했다면 수집·AI·공개를 반복하지 않는다. 직전 수집·분석 실패는 1, 공개 실패는 2·3을 유지한다. 진행 중 강제 종료된 `collecting`이나 유효한 결과 없는 실패 상태도 1이다. 정상 완료일 때만 0으로 건너뛴다. 상태 복구로 오늘을 차단한 마커도 1을 유지한다. 다음 한국시간 날짜에는 기존 하루 한 번 정책으로 다시 실행한다.

공개 단독 실행의 내보내기 경고 1은 기존 계약대로 정상 공개다. 일일 작업자는 이를 전체 0으로 정리하고 원래 `publish_exit_code=1`을 남긴다. 자식 종료 코드는 실행기가 그대로 전달한다. 코드 준비 실패는 일일1·공개2이며 날짜의 수집 시도를 소모하지 않는다.

## 기록과 복구

- `data/logs/runtime-YYYY-MM-DD.jsonl`: 코드 준비 또는 작업자 실행 결과. 예외 문자열 없이 종류와 종료 코드만 기록한다.
- `data/daily_status.json`, `data/logs/YYYY-MM-DD.jsonl`: 수집·분석·공개 상태와 날짜 게이트.
- `data/publish_logs/`: 실제 공개 단계 기록과 내보내기 보고.

준비 단계에서 멈췄다면 runtime 로그와 전용 저장소의 main·Git 인증·로컬 변경을 확인한다. 준비가 끝난 뒤 작업자가 시작하지 못한 경우도 runtime의 `phase=worker`와 실패 결과로 구분한다. 로그 쓰기 오류는 원래 종료 코드를 바꾸지 않는다. 잠금 충돌은 새 runtime 로그를 만들지 않으므로 CLI 출력과 실행 중인 작업을 확인한다.

강제 종료 후에는 부모·자식 Python과 관련 Git·Claude 프로세스가 모두 끝났는지 확인하고, 기존 운영 안내대로 상태·DB·카드·Git 이력을 대조한다. 부모만 강제 종료하고 작업자를 남긴 상태에서 새 작업을 시작하지 않는다. 손상 상태는 백업 후 `--recover-state`로 복구하며 날짜 마커를 삭제해 재시도를 유도하지 않는다.

기존 카드 전용 Git 정책은 유지한다. main 외 브랜치와 카드 외 로컬 커밋은 거부하며, 커밋·푸시는 `site/data/cards.json`만 대상으로 한다. 강제 푸시·자동 개발 커밋 푸시·의존성 자동 설치는 추가하지 않는다. 원격 코드에 새 의존성이 필요하면 운영자가 별도로 설치해야 한다. 최초 도입은 이 변경이 병합된 main을 운영 저장소에 직접 받아야 한다.

## #162 후속: 로컬 설정·날짜 확인·프로세스 종료

### 로컬 전체 설정의 한계와 긴급 중지

로컬 파일은 부분 덮어쓰기나 main 기본값과의 병합이 아닌 **설정 전체 사본**이다. main에서 필수 키·키 이름·버전을 바꾸면 오래된 로컬 파일이 검증에 실패할 수 있다. 이 경우 날짜의 수집 시도는 소비하지 않지만, 로컬 설정을 수정할 때까지 실행마다 종료 코드 1이 반복될 수 있다. 설정 형식 변경 PR에는 로컬 파일 변경 절차를 함께 적고, 운영자는 업데이트 후 dry-run을 통과시킨 뒤 예약을 재개한다. 자동으로 알 수 없는 키를 버리거나 임의로 기본값을 덧붙이지 않는다.

main의 `enabled=false`·`push=false`도 로컬 파일의 값보다 우선하지 않으므로 원격 파일 변경만으로 운영 PC를 긴급 차단할 수 없다. 긴급 중지할 때는 해당 Windows 예약을 먼저 중지·비활성화하고 로컬 파일의 enabled를 false로 바꾼다. 이미 실행 중인 작업은 설정 파일 수정만으로 끝나지 않으므로 프로세스 종료와 상태도 확인한다. 추적 기본값만 검사할 때는 `load_publishing(path, use_local=False)`를 사용한다. 기본 호출은 기존대로 운영 로컬 파일을 우선한다.

이관 전에는 추적 설정과 로컬 설정을 각각 검증한다. 유효한 로컬 파일이 있다는 이유로 잘못된 추적 파일을 자동 복구해 버리지 않는다. `.gitignore`는 모든 `*.local.toml`과 `pipeline/config/tmp*`를 제외해 다른 이름의 운영 사본·강제 종료 후 임시 파일도 Git에 들어가지 않게 한다.

운영 설정은 `pipeline/config/publishing.local.toml`에 전체 TOML로 보관한다. 파일이 있으면 같은 폴더의 기본 `publishing.toml`보다 우선하며 동일한 형식 검증을 거친다. 모델·상한·활성화·이미지·푸시 등 모든 운영 값이 로컬 파일을 따른다. 계정 정보는 넣지 않는다. 신규 운영자는 기본 파일을 로컬 이름으로 복사한 뒤 설정한다. 로컬 파일은 Git에서 제외한다.

기존 운영 PC처럼 추적 파일에 직접 설정을 바꿨다면 첫 코드 준비가 이를 자동 이관한다. 먼저 설정을 검증하고 원본을 비공개 `pipeline/data/config_backups/`에 보관한다. 로컬 파일이 없으면 원본 그대로 사본을 만들고, 있으면 기존 로컬 값을 검증·유지한다. 이후 **백업한 추적 설정 한 파일만** `git restore --source=HEAD --worktree -- pipeline/config/publishing.toml`로 복구한 뒤 원격 main을 동기화한다. Git의 줄바꿈 처리를 유지하며 다른 작업 파일이나 이력은 초기화하지 않는다. 로컬 설정이 없을 때의 기본 비활성화도 유지한다. 새로운 main의 운영 기본값을 쓰려면 로컬 파일을 검토·수정한다.

**로컬 설정에 없는 선택 칸 알림 (#154 후속):** 기본 `publishing.toml`에 적힌 선택 칸(`images`·`cross_model`)이 로컬 파일에 칸째 없으면, main에서 켜도 운영은 기본값(끔)으로 돈다. 이관본이 그 칸을 넣기 전의 설정을 옮긴 경우다(#158의 `images = true` 뒤 #168 이관). 매일 실행은 이를 막지 않고, 일일 로그에 `publish_config_notice`(`reason: local_config_missing_options`, `options`)를, 날짜 상태에 `publish_unset_local_options`를 남기고 표준 오류에 `[설정 확인]` 줄을 쓴다. 켜려면 로컬 파일에 칸을 적는다. 로컬에 `images = false`처럼 적어 둔 칸은 운영자의 선택으로 보고 알리지 않는다. 기본값을 로컬에 자동으로 덧붙이지는 않는다(위 원칙).

로컬 수정 파일이 있으면 동기화가 막힐 수 있다. 자동 이관 대상은 위 공개 설정뿐이며, 다른 코드·설정의 로컬 수정이 원격 변경과 충돌하거나 공개 설정이 스테이지돼 있으면 여전히 중단한다. 이때 `git status`와 runtime 로그를 확인하고 원본·설정을 백업한 뒤 개발 변경은 별도 브랜치에서 정리한다. `reset --hard`나 일괄 파일 복구로 우회하지 않는다. 잘못된 로컬 TOML도 사본을 보존한 뒤 형식을 고친다. Git 인증·네트워크 실패 자체를 무시하고 이전 코드로 공개하는 경로는 추가하지 않는다.

같은 날의 결과 확인은 Git 준비보다 먼저 수행한다. 성공·실패·중단의 기존 종료 코드를 오프라인에서도 유지하고 수집·AI를 반복하지 않는다. 잠금 충돌로 일일 작업을 건너뛰어도 날짜 JSONL에 흔적을 남긴다. 손상 날짜 상태는 실패로 멈추며 날짜 파일을 삭제하지 않는다.

### Windows 종료 확인과 보완

2026-11-18 운영 PC에서 실제 예약과 별개인 임시 예약을 만들었다. 동일한 숨김 PowerShell 진입점 뒤에 Python 부모·작업자·손자(단순 대기)를 연결하고 실행 제한을 1분으로 설정했다. 네트워크·AI·실제 수집은 없었다. 변경 전에는 약 85초 후 PowerShell은 끝났지만 Python 3개가 남았다. 임시 작업과 남은 합성 프로세스는 정리했다.

보완 후 동일 시험에서는 약 62초에 전체 4개 프로세스가 종료됐다. 실제 오전 8시 작업의 정의와 1시간 제한은 변경하지 않았다. 현재 Python 부모를 Windows Job Object에 넣어 새 자식이 생성될 때부터 같은 종료 단위를 상속하게 한다. 부모만 종료되면 KILL_ON_JOB_CLOSE로 하위 작업도 종료된다. 실행 스크립트는 실제 PowerShell PID를 내부 환경변수로 전달하고, 부모는 해당 프로세스 핸들의 종료를 기다려 PowerShell만 끝난 경우도 Job 전체를 종료한다. PID를 반복 조회하거나 종료 뒤 재사용된 PID를 추적하지 않는다. 실행기 PID 환경변수는 스크립트 종료 때 원래 값으로 복구한다.

Job 핸들은 Python 부모만 보유하고 일반 반환 시 임의로 닫지 않는다. 프로세스 종료 때 OS가 닫는다. 보호 설정을 만들지 못하면 새 작업자를 실행하지 않고 실패한다. Windows 8 이상 중첩 Job이 전제이며 Linux에는 이 Windows 보호를 적용하지 않는다. 전체 강제 종료에서는 finally 로그가 실행되지 않을 수 있으므로 기존 날짜 실패 마커·예약 결과·runtime 기록을 함께 확인한다. [Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)의 자식 상속·중첩·종료 계약을 사용한다.

실행기 PID는 숫자 범위뿐 아니라 현재 Python의 실제 상위 프로세스 체인에 있는지도 확인한다. 가상환경 리다이렉터가 끼어 있어도 상위 체인을 따라 확인하며 자신이나 형제 프로세스는 허용하지 않는다. 검증 후 종료 대기용 프로세스 핸들을 사용한다. 이 내부 환경변수는 Git과 새 작업자 환경에서 제거해 Claude 등 후속 자식에게 전달하지 않는다.

최초 배포는 기존 운영 폴더의 설정과 데이터를 백업하고 이 PR이 병합된 main을 받아야 한다. 운영 설정은 자동 이관 때까지 현재 위치에 유지하며, 코드가 아직 없는 운영 폴더에서 추적 설정만 미리 복구하지 않는다. 예약 재등록은 필요 없다.

첫 수동 업데이트에서 기존 설정 수정 때문에 `git pull --ff-only`가 거부되면, 공개 설정을 먼저 외부 비공개 위치에 복사하고 **그 파일만** `git stash push -- pipeline/config/publishing.toml`로 보관한다. main을 받은 뒤 보관한 설정을 `publishing.local.toml`로 복사하고 `collector.daily --dry-run --publish-config config/publishing.toml`로 확인한다. 이관한 설정은 추적 파일로 다시 덮어쓰지 않는다. 정상 확인 전에는 백업과 해당 stash를 삭제하지 않으며 다른 작업 파일에 충돌이 있으면 중단한다.

임시 데이터로 수동 공개 충돌, 수집·분석 실패 재실행, 중단 상태를 검증한다. 임시 코드와 실제 Python 자식으로 갱신된 내보내기 차단 정책이 첫 실행부터 적용되는지, 부모 잠금이 자식 실행 중 유지되고 종료 후 해제되는지 확인한다. 기존 임시 Git 원격 테스트로 카드 전용 커밋·경합·재시도 제한을 유지한다. 실제 학교 요청·Claude 호출·운영 예약 변경·카드 배포는 이 검증에서 실행하지 않는다.
