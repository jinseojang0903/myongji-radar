# 본문 규칙 기반 분류와 정보 추출 v1

2026-11-04 구조 정리: 실행 위치는 `pipeline/`으로 바뀌었다. 현재 실행법은 [파이프라인 README](../../pipeline/README.md)를 따른다. 아래 결과는 구현 당시의 검증 기록이다.

작성일: 2026-11-02

수집한 원문을 바꾸지 않고 저장된 공지 JSON을 분석하는 단계를 구현했다. AI·OCR·첨부파일 해석 없이 실행된다. 원문 버전 ID, 규칙 버전, 설정·코드·입력 해시를 기록하며 추출 결과는 사람 검수 전으로 유지한다.

## 실행

BAT 실행기에서 6번으로 기존 수집 결과를 분석하고, 7번으로 검수 목록을 연다. 새로 수집한 내용을 분석하려면 1번 또는 2번으로 수집한 뒤 6번을 실행한다. 분석 자체는 인터넷을 사용하지 않는다.

```powershell
.\launcher.bat analyze
# 또는
.\.venv\Scripts\python.exe -m collector analyze
# 변경한 규칙 파일로 실행
.\.venv\Scripts\python.exe -m collector analyze --rules config/rules.toml
```

## 구현 구조

- `config/rules.toml`: 활동 유형별 키워드, 일반 공지 키워드, 규칙 버전.
- `collector/rules.py`: 분류, 날짜, 자격 언급, 장소와 근거 추출. 네트워크·DB를 사용하지 않는 함수.
- `collector/analysis.py`: 저장 JSON 입력, 결과·검수 목록·이력 생성.
- `data/analysis.json`: 프로그램에서 읽는 검수용 결과.
- `data/analysis_review.md`: 원문 링크·필드·근거·안내를 함께 보는 검수 목록.
- `data/analysis_history/`: 입력·설정·엔진이 다른 결과를 별도 파일로 보존. 같은 조합은 중복 저장하지 않음.

현재 결과는 로컬 검수용이다. 결과 공지·일반 공지의 본문이나 개인 정보를 웹에 그대로 게시하는 용도로 사용하지 않는다.

## 분류

활동 여부는 `candidate` / `non_activity` / `needs_review`다. 활동 유형은 공모전·경진대회, 해커톤, 프로젝트, 교육, 멘토링, 서포터즈 등으로 구분한다. 넓은 학생 활동 후보를 모으는 규칙으로, candidate가 곧 공모전이라는 의미는 아니다.

공지 성격은 모집, 연장, 변경, 취소, 결과, 결과 발표 연기, 미상으로 구분한다. 제목의 성격을 우선하므로 결과 공지 본문에 과거 모집 내용이 있어도 신규 모집으로 바꾸지 않는다. 제목에 채용·일반 학사 신호가 있으면 활동 키워드가 본문에 우연히 등장해도 일반 공지로 처리한다.

`open_for_application`은 항상 null이다. 모집 중 여부나 개인별 참가 가능 여부는 아직 판정하지 않는다. `eligibility_decision`도 `not_evaluated`로 둔다.

## 날짜

신청·접수 일정, 제출 일정, 행사·교육 일정을 분리한다. 명시적인 항목명과 콜론 다음의 날짜를 대상으로 한다. HTML의 span 때문에 글자가 여러 줄로 분절되어도 공백을 제거한 검색 뷰에서 찾고, 근거는 원문 문자열의 정확한 시작·종료 위치로 돌려준다.

- 신청 마감과 작품 제출 마감을 섞지 않는다.
- 연도 없는 날짜는 게시 연도나 제목의 연도로 채우지 않고 확인 필요로 둔다.
- 같은 명시적 범위 `2026.8.26 ~ 09.11`에서만 두 번째 날짜의 연도를 공유한다. 연도를 공유했다는 근거도 기록한다.
- 마감 시각이 없으면 null이다. 23:59를 자동 생성하지 않는다.
- `접수: 2026.11.4`처럼 시작·마감 역할이 모호하면 날짜 후보만 보존하고 대표 마감은 비운다.
- 복수 일정이나 역전된 날짜, 잘못된 날짜·시각은 확인 필요로 둔다.
- `13:30-17:00`을 달력 날짜 두 개로 오인하지 않고 같은 날짜의 시간 범위로 처리한다.
- 복잡한 표, 일(day)만 줄여 쓴 범위, 콜론 없는 일정은 자동 확정하지 않는다.

기간 값의 `dates`에는 날짜 후보를, `start`와 `end`에는 명확한 범위·마감만 넣는다. 날짜가 null이거나 `needs_review`인 후보를 확정 마감으로 사용해서는 안 된다. 행사 단일 날짜는 `boundary=event_date`와 `dates`로 제공한다. 행사에는 심사·시상 등의 일정도 함께 발견될 수 있어 대표 행사일로 자동 선택하지 않는다.

## 자격과 장소

학년, 학적, 참가 캠퍼스, 전공, 팀 인원, 개인·팀 참가의 **명시적 언급**을 찾아 근거와 함께 저장한다. 허용·제외·대표자 조건이 섞일 수 있어 v1의 자격 필드는 값이 있어도 `needs_review`다. 예를 들어 `휴학생`이라는 단어를 찾았다고 휴학생 참가 가능으로 해석하지 않는다. 자격 항목 전체의 근거도 별도로 제공해 부정 문구와 예외를 함께 확인할 수 있다.

정규학기 학부 재학생이라는 문구를 특정 전공 제한으로 해석하지 않고, `2026학년도`의 마지막 숫자를 `6학년`으로 오인하지 않도록 한다. 팀 구성원의 비율을 팀 인원으로 해석하지 않는다.

`eligible_campuses`는 참가 조건 구간에서만 찾고, `venue_campuses`는 장소 항목에서 찾는다. 게시한 부서 이름이나 문의처의 인문·자연 캠퍼스는 참가 캠퍼스 조건으로 사용하지 않는다. 행사 장소가 자연캠퍼스여도 참가 대상이 자연캠퍼스 학생으로 제한됐다고 판단하지 않는다.

## 이미지·첨부 안내

이미지 전용 글에는 원문에서 일정·참가 조건을 확인하도록 안내한다. 본문 텍스트와 이미지가 함께 있으면 본문에서 찾은 값은 유지하고 추가 확인 안내를 붙인다. 첨부가 있으면 신청 전 추가 조건을 확인하도록 안내하되, 첨부가 있다는 이유로 본문 결과를 지우지 않는다.

원문에서 조건을 찾지 못한 상태는 `not_stated`이며, 이것은 제한 없음을 뜻하지 않는다. 지원하지 않는 표현이거나 이미지·첨부에만 조건이 있는 경우도 포함한다.

## 현재 데이터에서 확인한 결과

저장된 35건을 분석한 최초 분포는 활동 후보 27건, 일반 공지 7건, 활동 여부 확인 필요 1건이다. 공지 성격은 모집 20건, 결과 3건, 결과 발표 연기 1건, 모집 연장 2건, 미상 9건이다. 이미지 전용 공지 6건에는 추가 확인 안내가 붙었다. 이 숫자는 처리 분포이며 정답표로 측정한 정확도가 아니다.

실제 사례 대조에서 창업스토리 PT 공지의 `접수: 11월 4일`은 마감 역할을 확정하지 않았다. 제약바이오 아이디어 경진대회는 2026-10-28~2026-11-08 접수 기간을 추출했고 시각은 비워 두었다. ABI-X 해커톤에서 인문캠퍼스 참가 조건을 발견했지만 팀 인원·개인 신청·운영 중 팀 재구성은 근거를 함께 확인하도록 남겼다. AI 리터러시 예선 결과 발표 글은 결과 공지로 분류하고 제출 마감과 행사 장소를 분리했다.

현재는 사람의 검수 결과를 가져와 확정하는 기능, 학년·전공 조건의 완전한 논리화, 동일 행사 병합, 모집 중 여부 및 개인별 참가 가능 판정은 구현하지 않았다. 이 기능은 조건 언급 추출의 안정성을 확인한 뒤 추가한다.

검증: 기존 수집 테스트를 포함해 총 23개 테스트가 통과했다. 실제 35건의 원문 버전 연결과 본문 근거 109개의 오프셋·인용 문자열 일치를 확인했다. 최종 필드 350개 중 규칙 추출 23개, 확인 필요 38개, 본문에서 확인하지 못함 289개였다. 이는 자동 채움 범위가 제한적인 초기 버전임을 보여주는 처리 집계이며 정확도 수치는 아니다. BAT의 분석 명령과 메뉴 종료도 확인했다.
