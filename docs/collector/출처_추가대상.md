## 상세 표본 검증

각 출처를 현재 CLI의 미수집 일반 글 우선 정책으로 5건씩 수집했다. 제목·본문 텍스트·이미지 URL·첨부 다운로드 URL의 저장 결과를 저장된 HTML과 비교했다.

| 출처 | 상세 수집 | 구조 검사 | 텍스트 있는 본문 | 이미지 링크 | 첨부 링크 |
| --- | --- | --- | --- | --- | --- |
| 학생활동공지 | 5/5 | 20/20 | 2/5 | 6 | 0 |
| 진로/취업/창업공지 | 5/5 | 20/20 | 5/5 | 16 | 1 |
| 정보통신공학전공 | 5/5 | 20/20 | 5/5 | 1 | 4 |
| 에너지 소재 사업단 | 5/5 | 20/20 | 5/5 | 0 | 0 |

전체 20건에서 오류 없이 저장됐고 구조 검사 80개가 통과했다. 이는 **파싱 결과와 HTML의 구조적 일치**이며 날짜·참가 자격 해석 정확도나 전체 공지 누락률은 아니다. 최초 실행은 미수집 글만 있었으므로 모두 신규였다. 고정 글은 일반 글 다음에 처리하므로 이 표본을 단순히 ‘가장 최신 5건’이라고 해석하지 않는다.

학생활동공지는 이번 5건 중 3건이 이미지 전용이었다. 해당 글의 본문 0자는 파싱 실패가 아니며 이미지 링크를 보존했다. 이미지 내용은 읽지 않았고, 다운로드는 #12 범위다. 텍스트가 있는 표본에는 동영상이 포함된 PM 안전수칙 안내도 있었다. 현재 수집기는 동영상 파일을 내려받거나 별도 미디어 필드로 내보내지 않으며, 상세 원문 링크와 HTML을 보관한다.

## 교차 게시와 후속 범위

본교 141·146·853 및 부서 게시판에 같은 행사 공지가 있어도 출처별 원문 ID를 유지한다. 예를 들어 [본교 진로 공지의 11월 취업멘토링](https://www.mju.ac.kr/bbs/mjukr/146/236606/artclView.do)은 [대학혁신지원사업 게시판의 취업멘토링](https://innov.mju.ac.kr/bbs/innovation/56/236671/artclView.do)과 행사 병합 검토 대상이다. 이번에는 제목이 유사하다고 자동 삭제·병합하지 않았다. #16에서 날짜·대상·행사 동일성을 확인하고 연결해야 한다. 원문 파일 내용 변경 감지·다운로드는 #12, 항목 오류 격리·요청 제한 강화는 #11 범위다.

## 재현

`pipeline/`에서 Python 3.11 이상과 설치된 의존성으로 실행한다. 실제 수집에는 인터넷이 필요하다. 같은 날 전체 출처를 반복 수집하지 않고, 개발 중에는 저장된 원문으로 오프라인 점검한다.

```powershell
.\.venv\Scripts\python.exe -m collector run --source mju_student --limit 5
.\.venv\Scripts\python.exe -m collector run --source mju_career --limit 5
.\.venv\Scripts\python.exe -m collector run --source mju_ince --limit 5
.\.venv\Scripts\python.exe -m collector run --source mju_energy --limit 5
.\.venv\Scripts\python.exe scripts/audit_samples.py --source mju_student --source mju_career --source mju_ince --source mju_energy
```

실행 기록은 로컬 `pipeline/data/collector.sqlite3`, 상세 HTML은 `data/raw/`, 점검 결과는 `data/audit/structural_report.json`에 있다. 원문·DB·RSS 응답을 저장소에 올리지 않는다. 단위·통합 테스트는 인터넷 없이 실행되며, 점검 도구의 기존 기본 대상 유지·새 출처 명시 선택·미등록 ID 오류도 검증한다.
