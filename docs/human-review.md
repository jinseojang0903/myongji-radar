# 사람 검수 방법 (#99)

카드의 신청기간·자격은 팀이 원문과 대조하기 전까지 화면에 **확인 전**으로 보이고, 맞춤 추천은 "신청 가능" 대신 "확인 필요"를 냅니다. 팀원이 원문과 대조해 맞다고 확인한 항목만 **검수 완료**가 됩니다.

준비물은 Node.js 22 이상과 저장소 클론입니다. 운영 PC가 아니어도 됩니다.

## 순서

1. 사이트에서 검수할 카드를 엽니다. 주소 `card.html?id=` 뒤가 카드 id입니다.
2. 저장소 루트에서 실행합니다.
   ```
   git pull
   npm run review -- <카드 id>
   ```
   - 항목마다 지금 값, 메모, 근거 문장, 원문 링크가 나옵니다.
   - 항목 아래에 `[[review]]`로 시작하는 칸이 함께 나옵니다.
3. 원문 공지를 열어 항목마다 대조합니다.
   - **값**이 원문과 같은지 봅니다. 날짜, 시각, 캠퍼스·학년·학적 범위, 인원을 확인합니다.
   - **근거 문장**이 원문에 있고 그 값을 뒷받침하는지 봅니다.
   - 포스터·첨부에만 있는 조건이 값에 빠졌으면 **맞지 않은 것**으로 봅니다.
4. 맞은 항목의 칸만 `pipeline/config/human_reviews.toml` 맨 아래에 붙여 넣습니다. 칸의 글자는 고치지 않습니다.
5. 브랜치를 만들어 PR을 올립니다. 다음 매일 공개 때 그 항목이 검수 완료로 바뀝니다.

틀린 항목은 칸을 붙이지 말고, 카드 id·항목·원문에 적힌 내용을 이슈로 남겨 주세요.

## 무엇부터 할까

- 판정에 쓰이는 다섯 항목이 먼저입니다: 신청기간(`apply`), 캠퍼스(`campus`), 학년(`grades`), 학적(`enrollment`), 팀 인원(`team`). 이 다섯이 모두 검수 완료여야 "신청 가능"이 나올 수 있습니다.
- 접수 중인 카드, 그다음 마감일이 없는 카드 순서로 합니다. 마감된 카드는 하지 않아도 됩니다.

## 알아 둘 것

- **검수는 그때 본 값과 근거에 묶입니다.** 공지가 바뀌거나 다시 뽑혀 값·근거가 조금이라도 달라지면 검수가 풀립니다. 그러면 내보내기 보고에 "검수 기록이 지금 값·근거와 달라"로 남습니다. 다시 검수해서 그 칸을 새 칸으로 바꿉니다.
- **문의처(`contact`)는 검수 대상이 아닙니다.** 공개 전에 담당자 이름이 있을 수 있는 근거와 메일을 비워서, 화면만으로는 대조할 수 없습니다.
- 이 파일은 공개 저장소에 올라갑니다. 검수한 사람 이름이나 메모를 쓰지 않습니다. 값은 이미 공개된 카드 값입니다.
- 근거 문장이 너무 짧거나 잘려서 판단할 수 없으면 맞지 않은 것으로 보고 이슈로 남깁니다.
