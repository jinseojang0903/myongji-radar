# 열린 화면의 시간 갱신 (#150)

## 동작과 선택 근거

실제 데이터는 `loadPage()`가 반환하는 `getNow()`를 재계산마다 호출한다. 홈 검색·필터·통계, 추천 조건·제목 검색, 상세 마감·자격 판정이 페이지를 열었던 시각에 고정되지 않는다. 예시 파일 또는 `sample=true` 데이터는 기존처럼 `generated_at`을 기준으로 계산한다.

공통 `watchPageTime`은 분 경계 직후 시각을 확인하고 한국시간 날짜·신청 마감 여부·단계별 일정의 지난 여부·경고 문구가 달라졌을 때만 다시 그린다. 계약상 마감 시각이 분 단위이므로 매초 계산할 필요가 없다. `generated_at`은 초·밀리초가 있을 수 있어 36시간 경고는 별도로 해당 경계 직후를 예약한다. 실제 브라우저의 부하·절전·타이머 제한으로 표시 갱신이 지연될 수 있으며, 탭 복귀·창 포커스·뒤로 가기 복원 때 현재 시각으로 다시 확인한다. 숨긴 탭의 타이머는 중지한다.

날짜 판정은 기존 `deadlineOf`·`calendarItems`·`judgeCard`를 그대로 사용한다. 마감 시각과 정확히 같은 순간까지는 신청 가능 시간이고, 그 직후부터 마감이다. 시각이 없는 날짜는 한국시간 다음 날부터 마감이다. 예시에는 시간 갱신 타이머를 만들지 않는다.

상세에서는 마감 타일·내 조건 판정과 달력 일정의 지난 상태만 갱신한다. 근거 표와 문의 초안은 교체하지 않고, 달력의 향후 일정·알림 선택도 유지한다. 지난 일정은 선택을 해제하고 비활성화한다. 파일 받기 버튼도 클릭 시점에 다시 확인해 타이머가 늦어도 지난 일정을 내려받지 않게 한다. 자동 목록 갱신 후에도 같은 카드의 링크·버튼이 남으면 키보드 포커스를 유지하고, 마감으로 카드가 사라지면 결과 안내로 이동한다.

시간 갱신은 최초에 읽은 카드 파일을 기준으로 한다. 새 공지·운영자가 바꾼 카드 파일은 페이지를 새로 열어 확인한다. 자동 재요청·로그인·서버·모델 호출·조건 저장은 추가하지 않는다. JSON 형식과 판정 규칙 자체도 바꾸지 않는다.

## 회귀 검증

### #164 리뷰 후속

신청 시작 시각(시각이 없으면 한국시간 0시)의 경과 여부도 감시한다. 기준 계산·렌더·포커스 복원 예외는 고정 문구로 알리고, 다음 확인 예약은 finally에서 수행한다. 마지막 성공 기준은 렌더와 포커스 복원까지 끝난 뒤에만 저장해 같은 변경을 다음 확인에서 다시 시도한다. 원문이나 외부 오류 문자열은 로그에 넣지 않는다.

Node 회귀에 기준 계산 실패·렌더 실패 후 재시도, 신청 시작 경계, 실제 activeElement 대역을 둔 링크·버튼 유지·카드 제거·버튼 제거 7개를 추가했다. Edge 합성 시계에서도 시작 전 안내 제거와 일회성 렌더 실패 후 자동 복구를 확인했다.

PR #166 추가 리뷰: 시작 전 판정은 rules.js의 `isBeforeApplyStart`를 규칙과 시계가 함께 사용한다. 첫 기준 계산 실패도 회귀로 확인한다. 연속 실패는 성공할 때까지 고정 오류 한 번만 알리고, 복구 후 새 실패는 다시 한 번 알린다. 렌더가 DOM을 바꾸다 실패한 경우에도 finally에서 원래 카드의 포커스를 복원한 뒤 다음 확인에서 다시 시도한다.

`node --test tests/page_clock.test.js`는 실제 `loadPage`와 공통 시계를 DOM·fetch 대역 및 Node 가짜 시계에 연결한다. PC 시각과 실제 데이터를 변경하지 않는다.

- 재계산: 09:59의 신청 가능 카드가 10:01에는 홈·추천에서 제외되고 상세 판정이 불가로 바뀜.
- 명시된 마감: 10:00:00.000에는 열려 있고 10:00:00.001에는 마감으로 자동 갱신.
- 한국시간 자정: 시각 없는 마감 종료와 D-day·기준일 변경.
- 정보 경고: `generated_at`의 초·밀리초를 보존한 36시간 경계와 시계 되돌림 시 경고 해제.
- 탭 복귀·창 포커스 중복·뒤로 가기 복원·감시 해제.
- 바뀐 내용 없는 분에는 다시 그리지 않음, 출품 단계만 마감된 경우도 갱신.
- `sample=true` 및 실제 파일 404 후 예시 대체 시 기준일 고정.

2026-11-17, 로컬 합성 데이터와 Edge `157.0.4341.60`의 실제 브라우저 엔진으로도 확인했다. DevTools Protocol로 해당 페이지의 Date·타이머만 제어했고 PC 시각은 바꾸지 않았다. 실제 탭을 추가해 다른 탭으로 이동했다가 복귀하는 동작도 확인했다. 제품 코드에는 가짜 시계나 시험용 전역 함수를 넣지 않았다.

| 화면·조건 | 확인 결과 |
| --- | --- |
| 홈, 마감·36시간 경고 통과 | 카드 제외·통계·경고 갱신 |
| 추천, 마감 후 제목 검색 | 마감 카드 제외, 입력한 검색어 유지 |
| 상세, 신청 마감 통과 | 마감됨·불가 표시, 지난 일정 비활성화 |
| 상세, 근거를 펼치고 향후 일정·알림 선택 변경 | 펼친 상태와 선택 유지 |
| 홈, 자동 갱신 중 키보드 포커스 | 남은 카드의 포커스 유지, 제거된 카드는 결과 안내로 이동 |
| 실제 탭 전환 중 마감 통과 | 복귀 즉시 현재 시각으로 갱신 |
| 한국시간 자정·예시 데이터 | 실제 데이터는 갱신, 예시는 기준일 고정 |

직접 확인할 때는 운영 폴더와 분리한 임시 사이트 사본에서 합성 카드의 `fields.apply.value.end`를 가까운 분으로 설정하고 `time_given=true`로 둔다. 홈·추천·상세를 마감 전에 열고 입력 없이 기다리는 경우와 다른 탭에서 돌아오는 경우를 각각 확인한다. 시각 없는 날짜 마감과 36시간 경고는 위 가짜 시계 회귀로 재현한다. 운영 카드나 PC 시각을 바꾸지 않는다.
