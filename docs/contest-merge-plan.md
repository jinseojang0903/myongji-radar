# #16 분할 구현과 운영 전 확인

PR #73의 통합 초안은 기본 카드와 공개 경로까지 한꺼번에 바꾸어 검토 범위가 커졌다. 리뷰에 따라 다음 네 단계로 분리한다.

1. **PR #73: 게시일·버전 정보.** 공개 출처 날짜를 한국 날짜로 통일하고 비공개 버전·해시·모델 정보를 중간 묶음에 보존한다. 레거시 누락 목록을 처리한다. 병합·종료·차단 정리·publisher 옵션은 포함하지 않는다.
2. **별도 Draft: 수동 병합 코어.** 고정 그룹만 대상으로 별도 폴더에 미리보기 결과를 만든다. 병합할 수 없는 그룹은 기존 개별 카드를 유지하고 사유를 보고한다. 원문 추출값이나 미등록 카드를 변경하지 않는다. 차단 확대는 하나의 순수 함수로 관리하며 원래 차단 ID와 확장된 ID를 구분한다. 운영자의 차단 해제를 유도하는 경고를 만들지 않는다.
3. **#14 이후: 실제 근거 기반 마감 이력.** 실제 역사 영상 포스터의 이전 마감과 원문을 대조해야 한다. AI 리터러시의 본선 일정 충돌을 신청 마감 변경으로 기록하지 않는다. 종료·보류·복구 상태는 실제 사례와 운영자 해제 수단을 함께 검증한 뒤 도입한다.
4. **별도 검토: publisher 연결.** 검증 전 묶음은 공개하지 않는다. 기존 로컬 cards.json을 그대로 재배포하는 우회는 제공하지 않는다. 차단 변경이 병합 오류와 독립적으로 적용되고, 데이터 보존·되돌리기가 가능한지 검증한 뒤 연결한다.

기존 통합 초안은 커밋 `db83d6b`와 로컬 보존 브랜치 `16-original-integration-archive`에 남긴다. 해당 브랜치는 운영용이 아니다. 안전성 문제가 남은 이력·종료·publisher 코드를 현재 기본 경로에 연결하지 않는다. PR #73은 #16 전체 완료를 의미하지 않으며 이슈를 닫지 않는다.

## 기존 초안으로 시험한 환경의 되돌리기

1. 예약 작업을 중지하고 비공개 data 전체와 현재 공개 JSON을 백업한다. 로그·이전 원문·병합 상태를 삭제하지 않는다.
2. 배포 승인된 기본 브랜치 코드로 돌아온다. `--merge-contests`를 사용하지 않는다. 이 분할의 기본 publisher/exporter는 병합 상태 파일이 있다는 이유로 일반 실행을 차단하지 않는다.
3. 초안의 `card_bundles.merged.json`과 관련 시험 결과는 백업 폴더에 보존한다. 기존 그룹 ID를 차단했다면 구성 공지의 개별 ID도 검토해 차단 목록에 명시한다. ID를 바꿔 차단을 해제하지 않는다.
4. 새 원문·분석·추출 묶음으로 기존 검증 단계를 실행하고, 원문 대조와 차단 결과를 확인한다. 로컬 공개 JSON을 신뢰해 차단 카드만 빼서 재배포하지 않는다.
5. 팀원 검토 후에만 공개 연결과 예약 작업을 재개한다. 이전 초안의 이력·종료 기록은 새 기능이 준비될 때 별도 이관한다.

새 미리보기는 운영 data와 다른 임시 폴더에 만든다. 운영 입력·SQLite·공개 폴더를 출력 경로로 지정하지 않는다. 미리보기 파일을 직접 exporter에 연결하는 것은 이 단계의 지원 범위가 아니다.
