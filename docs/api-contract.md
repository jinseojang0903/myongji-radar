# 데이터 계약 (v0.1, 2026-11-02 초안)

파이프라인(`pipeline/`)이 만들고 사이트(`site/`)가 읽는 JSON 형식이다. 서버가 없으므로 "API"는 이 파일 형식을 말한다.
**형식을 바꿀 때는 이 문서를 먼저 고치고**, 파이프라인과 사이트를 같이 고친다. JSON 키는 영어, 화면 문구는 한국어로 쓴다.

### 비공개 수집 파일 계약 (#12)

`pipeline/data/notices.json`의 `images[]`·`attachments[]`는 기존 `url`·`alt` 또는 `name`을 유지한다. 다운로드 성공 시 `sha256`(파일 바이트), `local_path`(`assets/<sha256>.bin`), `size_bytes`, `download_status: "downloaded"`를 더한다. 이름·URL은 저장 경로에 사용하지 않는다. PDF·HWP 5·HWPX 첨부는 별도 제한 시간의 로컬 프로세스에서 텍스트로 변환하고 `text_path`, `text_status: "extracted"`를 더한다. OCR은 수행하지 않는다. 이미지·지원하지 않는 형식·암호 문서·스캔본·변환 실패는 `text_status: "needs_review"`, `text_reason`으로 원문 확인 필요를 남긴다.

첨부의 주소 정책·크기/개수/실행 예산 상한·HTTP 4xx(408/425/429 제외)는 `download_status: "skipped"`와 `download_error`(예외 종류만)를 남기는 경고다. 타임아웃·연결 오류·429·서버 오류·원본 파일 저장 실패는 `download_status: "failed"`인 실제 오류다. 같은 URL의 마지막 성공 파일이 있으면 해시·경로를 보존하되 **현재 다운로드에 성공했다는 뜻이 아니다**. 이후 소비자는 반드시 `download_status`를 확인해야 한다. 변환과 변환 텍스트 저장 오류는 다운로드 상태를 되돌리지 않고 `needs_review`와 안전한 사유만 남긴다.

본문과 다른 첨부는 계속 저장한다. 출처별 `runs.result_json`의 `warnings`와 `errors`, 일일 상태·JSONL의 각 건수를 따로 기록한다. 경고만 있으면 수집 종료 코드 0, 실제 오류가 있으면 1이다. 완료된 이번 수집에서 저장한 공지가 있으면 코드 1이어도 규칙 분석을 수행하되 최종 일일 종료는 1(`partial_failure`)이다. 저장한 공지가 없거나 실행이 미완료면 이전 분석을 유지한다. publisher 자동 호출은 아직 연결하지 않는다.

파일 해시는 내용 버전 판정에 포함하고 경로·시각·변환 상태·오류는 제외한다. 기존 링크만 있는 버전에 처음 파일 해시가 붙으면 새 버전이 생긴다. 같은 파일의 일시적 실패는 거짓 내용 변경을 만들지 않는다. 확인 상태 갱신은 최신 버전의 자산 메타데이터로만 제한하며 저장된 URL·게시일을 덮어쓰지 않는다. 같은 해시의 정상 텍스트 파일이 있으면 다시 변환하지 않는다.

모든 원본·변환 텍스트는 비공개 `data/` 아래에만 저장한다. 공개 카드 exporter는 이 경로와 파일 본문을 내보내지 않는다. #12는 수집·변환·해시 저장까지이며, AI 입력과 첨부 근거 대조 연결은 별도다.

## 1. `site/data/cards.json`

```json
{
  "schema_version": "0.1",
  "generated_at": "2026-11-05T09:00:00+09:00",
  "boards": [ { "id": "mju-general", "name": "메인 일반공지", "list_url": "https://..." } ],
  "cards": [ Card ]
}
```

- `boards[].list_url`: 게시판 목록 주소. 모르면 `null` (화면은 이름만 보여 준다).
- **오래된 정보 경고:** 실제 데이터의 `generated_at`이 36시간보다 오래됐으면(매일 갱신이 하루 넘게 멈춤) 화면 맨 위에 "대회 정보가 N일 전(시각) 기준"이라는 경고와 원문 확인 안내를 띄운다 (`site/js/cards.js` `bannerText`, #19). 파이프라인이 멈추면 어제 cards.json이 그대로 공개되기 때문이다.
- **예시 데이터** `site/data/cards.sample.json`은 같은 형식에 `"sample": true`와 `"sample_note"`(무엇이 예시인지)를 더한다. 화면은 `cards.json`이 없을 때만 예시를 읽고, 예시임을 상단에 표시하며, 기준일을 오늘 대신 `generated_at`의 날짜로 쓴다 (예시 대회가 이미 마감돼 목록이 비지 않도록).

### Card

| 키 | 형식 | 설명 |
|---|---|---|
| `id` | string | 대회 고유 id. 같은 대회가 여러 게시판에 올라와도 하나 (중복 병합 결과). **영문 소문자·숫자·하이픈 1~64자** (`^[a-z0-9][a-z0-9-]{0,63}$`, 주소 `card.html?id=`에 쓰임). 형식이 다른 카드는 화면이 뺀다 |
| `title` | string | 대회명 |
| `organizer` | string | 주관 |
| `scope` | `"교내"` \| `"외부"` | 교내 대회 / 학교 게시판에 홍보된 외부 공모전 |
| `sources` | Source[] | 이 대회가 올라온 공지들. 첫 번째가 최신 |
| `fields` | object | 항목별 값. 아래 Field 목록 |
| `deadline_history` | Change[] | 마감 변경 이력 (없으면 빈 배열) |
| `meta` | object | `prompt_version`, `extract_model`, `cross_model`, `checked_at` |

**Source:** `{ "board_id", "url", "title", "posted_at": "YYYY-MM-DD", "last_seen_at": "시간대 있는 ISO 8601 시각 | null" }`

- 공개 `boards[].id`와 `sources[].board_id`는 영문 소문자·숫자·하이픈 1~40자다. 기존 수집 설정·DB의 `mju_ctl` 같은 ID는 보존하고 공개 시 `mju-ctl`로 바꾼다. 두 내부 ID가 같은 공개 ID가 되면 설정을 고쳐야 한다.
- `posted_at`은 원문 게시 시각을 한국 시간(Asia/Seoul)으로 환산한 날짜다. 시간대가 없는 수집 게시 시각은 한국 시간으로 취급한다. 출처 최신순 정렬에도 같은 날짜를 사용한다.
- `last_seen_at`은 해당 공지를 마지막으로 성공적으로 확인한 시각이다. 원문 변경·분석 시각과 다르며, 과거 JSON만 있어 확인 시각을 모르면 `null`이다. 화면은 선택 정보로 취급한다.

파이프라인은 `pipeline/exporter`가 이 형식으로 내보낸다(#17: 계약 키만, 근거 200자·값 300자·항목당 근거 5개·카드당 근거 1,500자 상한, 링크는 화면 `safeUrl`과 같은 https·허용 도메인만, 개인 연락처 가림. 상세는 `pipeline/README.md`). 화면(`site/js/cards.js`의 `validateCardData`)은 읽을 때 형식을 한 번 더 검사하고, 틀린 카드·게시판만 빼고 건수를 표시한다 (카드 하나 때문에 화면 전체가 멈추지 않게).

**Change:** `{ "field": "apply_end", "old": "2026-09-30", "new": "2026-10-23", "old_source": url, "new_source": url, "checked_at": "YYYY-MM-DD" }`

### 검토된 공지 병합 (#16)

병합은 `pipeline/config/contest_groups.toml`에 사람이 확인해 등록한 `(source_id, external_id)` 묶음만 적용한다. 제목 유사도만으로 다른 연도·회차·캠퍼스 대회를 자동 병합하지 않는다. 묶음의 `id`가 고정 카드 ID이며 미등록 공지는 기존 공지별 ID를 유지한다. 병합을 켜면 기존 공지별 링크가 묶음 ID로 바뀌므로 배포 전 차단 목록과 공유 링크를 점검한다. 별칭 리다이렉트는 제공하지 않는다. 구성 공지의 기존 ID 또는 병합 ID가 수동 차단돼 있으면 전체 묶음을 제외해 ID 변경으로 차단을 우회하지 않는다.

중간 묶음의 공지에 `external_id`, `version_id`, `input_hash`, `version_number`를 비공개로 붙이고 meta에는 모델·프롬프트 지문을 보존한다. 수집 `notices.json`의 `version_number`는 해당 공지의 보존된 원문 버전 수다. 현재 수집·규칙 분석과 원문 버전/해시가 맞지 않으면 병합을 중단한다. 등록된 구성 공지의 수집·추출이 빠지면 해당 카드를 보류한다. 구성 공지가 모두 있고 원문에서 최종 결과·대회 자체 취소가 명확하며 그 공지가 다른 구성 공지보다 늦으면 종료한다. 예선 결과, 예정·일정 변경, 결과 연기, 신청자의 취소 등은 종료로 단정하지 않고 보류한다. 확인되지 않은 종료 후보는 같은 원문의 재추출만으로 보류가 해제되지 않는다. 결과·연기 공지 본문을 병합을 위해 AI로 추가 전송하지 않는다.

근거의 공지 번호는 게시일·내부 출처 ID 순서에 맞춰 다시 매긴다. 상충한 자격·일정은 최신 후보값을 남겨도 `conflict`/`needs_check`로 표시하고 사람 검수 상태를 자동 승계하지 않는다. 제목·주관·범위는 공개 계약에 별도 상태가 없으므로 추출값이 충돌하거나 인용이 원문에 없거나 대조 불가면 그룹을 보류한다. 인용의 존재가 추출값과 문맥의 의미가 일치한다는 뜻은 아니다. 병합 후 기존 검증기를 다시 통과시킨다.

마감 이력은 날짜가 유효하고 연도를 추정하지 않은 `found` 추출값의 차이로만 만든다. 후보 근거를 기존 검증기로 원문과 대조하고, 추출된 마감 날짜·시각이 인용문에서 실제 마감이나 날짜 범위의 끝인지 추가로 확인한다. 값과 인용이 다르거나 역할이 애매하면 이력을 만들지 않는다. 미대조 이미지·불일치·그 밖의 상식 오류도 제외한다. 늦게 재게시된 옛 공지의 마감이 게시일보다 이른 것만은 과거 이력 후보로 허용한다.

첫 병합의 서로 다른 공지는 원문과 대조된 명시적 연장·변경 문구, 이에 부합하는 규칙 공지 성격과 게시 순서가 있어야 한다. 같은 날짜의 미기재 시각이 새로 기재된 경우처럼 실제 마감이 바뀌었는지 알 수 없거나, 연장이라고 하면서 마감이 앞당겨지면 이력을 만들지 않는다. 수정 버전의 관측 순서가 불명확하거나 중간 관측이 확인되지 않아도 이력을 만들지 않는다. 같은 공지의 연속된 후속 원문 버전은 이전 병합 관측과 비교하되 버전 번호가 역행하면 병합을 중단한다. 이미 확인한 최종 종료는 다음 실행에도 보존한다. 모델·프롬프트가 다르거나 원문/입력이 같고 재추출값만 바뀐 경우는 실제 마감 변경으로 기록하지 않는다. 이미 공개한 이력의 신뢰도가 나중에 불명확해지면 이전 이벤트는 비공개 상태로 보존하되 공개 이력은 비우고 수동 검토를 요구한다. 이후 새 원문이 오더라도 이 보류를 자동 해제하지 않는다. 같은 마감의 반복 확인도 이력을 늘리지 않는다. 이력은 공식 일정 검수 완료를 뜻하지 않는다.

`data/card_bundles.merged.json`은 병합 묶음과 `merge_state`(비공개 관측값·이력)를 함께 원자적으로 저장해 재실행 시 비교한다. 별도 상태 파일과 묶음 파일의 불일치를 피한다. 기존 병합 ID나 구성 공지를 제거하려면 이력·차단 목록을 수동 이관해야 한다. 상태 파일이 있는 데이터 폴더에서는 병합 옵션 없는 publisher 실행과 이전 상태에 맞지 않는 exporter 입력을 거부한다. 보류된 그룹 때문에 결과가 비었다면 `--allow-empty`로도 전체를 덮어쓰지 않는다. 빈 목록 전체 갱신이 불가능할 때 기존 공개 목록에 차단된 그룹이나 구성 공지 ID가 있으면 차단 목록과 병합 상태를 대조해 그 카드만 제거한다. 다른 카드와 원래 기준 시각은 보존하며 종료 코드 1로 검토를 알린다. 공개 exporter는 기존 Card·Change 키만 내보내며 내부 버전/해시/모델 비교 상태는 공개하지 않는다. 운영 연결은 선택 옵션으로 시작하고, 설정·데이터가 잘못되면 기존 출력은 유지한다.

### Field (모든 항목 공통 형태)

```json
{
  "value": <항목별 형식, 정보가 없으면 null>,
  "status": "ai | auto_verified | needs_check | human_verified | missing",
  "evidence": [ { "quote": "원문 그대로 짧게", "location": "제목 | 본문 | 이미지 | 첨부", "file": "이미지·첨부 파일명(선택)", "source": url } ],
  "note": "애매하거나 충돌한 이유 (선택)"
}
```

| status | 화면 표시 | 뜻 |
|---|---|---|
| `ai` | AI 정리 | 추출만 됨, 검증 전 |
| `auto_verified` | 자동 검증 통과 | 근거 문장 실재, 모델 일치, 형식·상식 검사 통과 |
| `needs_check` | 원문 확인 필요 | 검증 실패, 정보 충돌, 해석 애매 |
| `human_verified` | 검수 완료 | 팀이 원문과 대조 |
| `missing` | 정보 없음 | 공지에 없음 (`value`는 null) |

### 내부 분석 저장 (`pipeline/data/collector.sqlite3`, 비공개)

`analyses`는 `notice_versions.id`를 외래 키로 갖는 분석 이력이다. 생성기 종류(`rule`/`ai`), 생성기 버전, 요청 모델과 실제 모델, 프롬프트 버전·지문, 입력 본문 해시, 결과 JSON, 실행 시각을 저장한다. 같은 원문 판·생성기·설정·결과를 다시 저장하면 중복을 만들지 않는다. 모델·프롬프트·규칙·원문이 바뀐 분석과 같은 설정으로 다시 추출한 다른 결과는 함께 남긴다. 파서 재해석으로 같은 원문 버전의 텍스트가 바뀌어도 입력 해시로 구분한다. 기존 DB는 버전·원문을 지우지 않고 스키마 v3로 자동 이전한다.

규칙 엔진의 내부 상태는 호환성을 위해 유지한다. `extracted`는 계약의 `ai`(자동 추출·검증 전), `needs_review`는 `needs_check`, `not_stated`는 `missing`으로 대응한다. 규칙 필드에는 이를 `contract_status`로 함께 기록한다. 이 대응은 **상태만** 바꾼다. 규칙의 `mentions`를 허용 조건으로 바꾸거나 필드 이름·값 형식을 AI 카드와 같다고 보지 않는다. 규칙 분석만으로 공개 카드를 만들지 않는다.

AI v0.2의 `found`는 검증 전 `ai`, `needs_check`·`conflict`는 `needs_check`, `missing`은 `missing`이다. 검증기·사람 검수만 `auto_verified`·`human_verified`로 올릴 수 있다. 기존 `analysis.json`·추출 캐시는 실행 호환용으로 계속 만들며, DB가 없는 JSON 전용 시험 입력은 DB를 새로 만들지 않는다. 모델 비교용 `extractor eval`의 다중 공지 결과는 기존 평가 폴더에 남긴다(공지 하나에 잘못 연결하지 않는다).

**핵심 항목 규칙:** `apply`(신청기간)와 자격 항목(`campus`, `grades`, `enrollment`, `team`)은 `human_verified`가 아니면 화면에 **확인 전**으로 표시한다.

## 2. 조건 (자연어 해석기 출력, 버튼 입력과 같은 형식)

`site/js/parser.js`가 문장을 이 형식으로 바꾸고, 학생은 칩으로 확인·수정한다. 확장 시 AI 해석기로 바꿔도 이 형식은 유지한다.

```json
{
  "campus": "인문 | 자연 | null",
  "grade": 1,
  "is_transfer": false,
  "enrollment": "재학 | 휴학 | 수료 | 초과학기 | 졸업유예 | null",
  "participation": "개인 | 팀 | null",
  "deliverables": ["영상"],
  "period": "마감임박 | 이번주 | 이번달 | null",
  "unknown_terms": ["해석하지 못한 표현"]
}
```

`null`은 학생이 말하지 않은 조건이다. 판정에서 "모름"으로 다룬다.

- 입력 문장은 **200자까지** (`MAX_INPUT_LENGTH`). 더 길면 해석기는 `RangeError`를 내고, 화면 입력창은 `maxlength`로 같은 값을 건다.
- `grade`: 정수 1~6 또는 `null` (추출 형식의 학년 범위와 같다).
- `is_transfer`: `true`·`false`·`null`. 편입 여부를 말하지 않으면 `null`.
- `deliverables`: 1절 `deliverables` 태그 중 `기타`를 뺀 7개에서 고른다. 말하지 않으면 빈 배열.
- `unknown_terms`: 해석하지 못한 표현(조사·어미를 뗀 형태). 없으면 빈 배열. 화면은 "이해하지 못한 표현"으로 보여 준다.

**해석 규칙** (`parser.js`와 시험 문장 정답 `eval/parser/`가 같이 따른다)

1. 뜻이 하나로 정해지는 표현만 값으로 바꾼다. 애매하면 값은 `null`로 두고 표현을 `unknown_terms`에 넣는다. 예: "고학년", "졸업반", "복학생", "2학년 이상", "3학년부터". 학과·단과대 이름은 캠퍼스로 바꾸지 않는다. **지금 상태가 아닌 캠퍼스·학년·학적·편입**("휴학 예정", "휴학 하려고", "편입 준비 중", "내년에 3학년", "1학년 때")도 애매한 것으로 본다. "편입 신입생"의 학년은 비운다 (편입생은 1학년이 아닐 수 있음). 캠퍼스 별칭: 서울캠=인문, 용인캠=자연. "신입생"·"새내기"는 1학년.
2. 같은 조건에 다른 값이 둘 이상 나오면(예: "1, 2학년", "인문캠이랑 자연캠") 그 조건은 `null`, 표현은 `unknown_terms`. 다만 참가 형태를 둘 다 말하면("혼자도 팀도 괜찮아") 상관없다는 뜻이므로 `null`만 둔다. 제출물은 여러 개를 모두 담는다.
3. 부정("아니고", "말고", "빼고", "없이", "안 했어")이 조건 바로 뒤에 붙으면: "편입생 아니고"·"편입 안 했어"는 `is_transfer: false`, "팀 말고"는 `participation: "개인"`(반대 값). 그 밖의 조건을 부정한 표현은 이 형식에 담을 수 없으므로 `unknown_terms`에 넣는다 (예: "영상 말고", "휴학 안 한").
   - **거절·곤란**("싫어", "별로", "부담돼서", "힘들어")은 참가 형태에서만 반대 값이다("팀플은 싫어" → `개인`). 다른 조건에서는 무엇을 말하는지 확실하지 않으므로 비운다("편입생이라 힘들어요" → `is_transfer: null`).
   - **무엇을 부정하는지 확실하지 않으면** 값을 비우고 문구를 `unknown_terms`에 넣는다: 부정이 몇 낱말 떨어져 있음("자연캠 학생은 아니에요", "같이 할 사람 없어서", "팀으로 참가 못해"), "못"("영상은 못 찍어"), 경험을 말하는 "안 해봤어". 참가 형태에 확실하지 않은 표현이 하나라도 있으면 참가 형태는 비운다.
   - 나열("휴학이나 수료", "영상과 발표", "인문캠 또는 자연캠")의 뒤쪽에 부정이 걸리면 나열 전체에 걸린 것으로 보고 앞쪽 값도 비운다("휴학이나 수료는 아니에요" → `enrollment: null`).
   - 같은 절에 지난 일·앞으로의 일을 말하는 표현("지난 학기", "지난해", "지난 겨울", "저번에", "전에", "작년", "옛날", "원래", "내년", "복학")이 있으면 그 절의 캠퍼스·학년·학적·편입은 비운다. 부정으로 읽은 값도 비운다("지난 학기에 편입 안 했어" → `is_transfer: null`).
   - "편입생은 안 돼?"처럼 자격을 묻는 말은 부정이 아니다.
   - 문장부호(쉼표·마침표·물음표·느낌표 등)가 절을 나눈다. 앞 절의 부정은 뒤 절의 조건에 걸지 않는다. 절이 부정으로 시작하면("편입생, 아니고 재학생") 앞 절의 마지막 조건을 비운다.
4. 조건과 상관없는 말(대회, 있어, 찾아줘 등)은 버린다. 그 밖에 해석하지 못한 낱말은 조용히 버리지 않고 `unknown_terms`에 남긴다.
5. `period`는 모두 **마감일 기준**이다. `마감임박`은 마감 7일 이내(홈 필터와 같다, "3일 안에 마감"·"마감 일주일 남은" 포함), `이번주`는 이번 주 일요일까지("이번 주말" 포함), `이번달`은 이번 달 말일까지. 그 밖의 기간 표현("다음 주", "11월", "10일 이내")은 `unknown_terms`.

## 3. 판정 결과 (`site/js/rules.js`)

`judgeCard(card, conditions, { now })` → 아래 형식. `now`는 판정 기준 시각(기본은 지금, 테스트·목업은 고정 날짜). 날짜는 한국 시간으로 본다.

```json
{ "card_id": "...", "result": "eligible | team_needed | check | ineligible",
  "reasons": [ { "field": "campus", "outcome": "fail", "message": "인문캠퍼스 재학생만 참가 가능 (내 조건: 자연캠)",
                 "quote": "근거 문장 | null", "unverified": true } ] }
```

| result | 화면 | 판정 순서 (위에서부터 하나라도 해당하면 그 결과) |
|---|---|---|
| `ineligible` | 불가 | 1. 근거가 있는 핵심 항목에 학생 조건이 맞지 않음, 또는 신청 마감이 지남 |
| `check` | 확인 필요 | 2. 판정에 필요한 핵심 항목이 `missing`·`needs_check`·확인 전이거나, 대회가 제한하는 조건을 학생이 입력하지 않음(`null`), 또는 개인 참가 학생인데 `team.individual_ok`가 `null` |
| `team_needed` | 팀 구성 시 가능 | 3. 개인 참가(또는 참가 방식 미입력) 학생인데 `team.individual_ok`가 `false` |
| `eligible` | 신청 가능 | 4. 위에 해당하지 않음 |

**핵심 항목:** `apply`, `campus`, `grades`, `enrollment`, `team`. 그 밖의 항목은 판정에 쓰지 않는다 (제출물·기간은 #24 화면의 필터).

**항목 상태와 판정**

| 항목 `status` | 학생 조건과 맞음 | 맞지 않음 |
|---|---|---|
| `human_verified` | 통과 | `ineligible` |
| `ai`, `auto_verified`, 그 밖의 값 (확인 전) | `check` ("확인 전") | `ineligible` + `unverified: true` (화면에 "확인 전 정보" 표시) |
| `needs_check` | `check` | `check` (애매한 값으로 불가를 내지 않는다) |
| `missing` | `check` | `check` |

**항목별 규칙**

- `apply`: `end`가 지났으면 불가. 시각이 없으면(`time_given: false`) 마감일 다음 날부터 불가로 보고, **마감일 당일은 `check`**(시각 미기재). `end`가 없으면(상시 접수 등) `check`. 시작 전이면 결과는 바꾸지 않고 `outcome: "note"`로 "신청 시작 전"을 남긴다.
- `campus`·`grades`: `"any"`면 학생 조건과 상관없이 통과. 목록이면 학생 값이 목록에 있어야 한다. 학생 값이 `null`이면 `check`. 빈 목록이나 숫자가 아닌 학년은 추출 오류로 보고 `check` (불가로 읽지 않는다).
- `enrollment`: 학생이 고를 수 있는 학적(재학, 휴학, 수료, 초과학기, 졸업유예)으로 판정한다. 학생 학적이 `excluded`에 있으면 불가. `allowed`가 비어 있으면 통과, 있으면 학생 학적이 그 안에 있어야 하고 아니면 불가(초과학기생이 `재학`에 포함되는지는 애매하므로 `check`). **학생 조건으로 답할 수 없는 표현이 있으면 맞든 안 맞든 `check`:** `allowed`의 위 다섯 낱말 밖 표현(원문 표현, `편입생`, `대학원생` 등), `excluded`의 표준 낱말 밖 원문 표현(예: "외국인 유학생"). 편입생(`is_transfer: true`)은 `excluded`에 `편입생`이 있으면 불가, 편입 여부가 `null`이면 `check`. `excluded`의 `기존 수상자`·`대학원생`·`졸업`은 결과를 바꾸지 않고 `note`로 남긴다. 학생 학적이 `null`이면 학적 제한(`allowed`가 있거나 `excluded`에 위 다섯 낱말이 있음)이 없을 때만 통과.
- `team`: `individual_ok`가 `true`면 통과. `false`면 팀 참가 학생은 통과, 개인·미입력은 `team_needed`. `null`이면 팀 참가 학생은 통과, 개인·미입력은 `check`.

**reasons:** 결과를 정한 사유가 앞에 온다 (`fail` → `unknown` → `team` → `note` → `ok`). `outcome`은 `fail`·`unknown`·`team`·`note`·`ok`. `eligible`의 `ok` 사유는 화면의 "맞은 조건 요약"에 쓴다 (✓ 표시는 화면이 붙이고 메시지에는 넣지 않는다). 확인 전 항목의 `ok`·`team`은 `unknown`이 되고 메시지 끝에 "(확인 전)"이 붙는다. `quote`는 그 항목 근거의 첫 문장, 없으면 `null`.

**안전 원칙:** 확실하지 않으면 `eligible`을 내지 않는다. "불가인데 가능으로 판정"(위험 오판)을 가장 나쁜 오류로 보고 따로 센다. `eligible`은 핵심 항목 5개가 모두 `human_verified`이고 모두 학생 조건과 맞을 때만 나온다.

```json
  "accuracy": [ { "method": "규칙만 사용", "filled": Measure, "field_accuracy": Measure, "risky_misreads": Measure } ],
  "prompts": [ { "version": "v0.1", "date": "YYYY-MM-DD", "changes": "바꾼 것", "reason": "이유", "accuracy": Measure, "path": "prompts/..." } ],
  "ai_errors": [ { "date": "YYYY-MM-DD", "where": "어느 작업", "ai_did": "AI가 틀린 것", "caught_by": "잡은 방법", "fix": "고친 것", "path": "근거 문서 | null" } ],
  "quiz": [ { "id": "영문 소문자·숫자·하이픈", "kind": "사례 종류", "question": "질문", "quotes": [ { "text": "원문 그대로", "location": "본문 | 이미지 | 첨부", "url": "https://... | null" } ],
              "options": ["보기1", "보기2", "보기3"], "answer": 2, "explanation": "해설", "path": "근거 문서 | null" } ],
  "tools": [ { "name": "도구", "used_for": "쓴 곳", "status": "사용 | 예정", "issue": "#15 | null" } ]
}
```

- **Measure:** `{ "value": 23, "total": 350, "unit": "항목", "note": "공지 35건", "measured_at": "YYYY-MM-DD", "source": "어디서 쟀는지" }` 또는 `null`. **`null`이면 화면은 "측정 중"**으로 보여 준다. 수치는 **개수(`value`, 정수)와 전체 수(`total`)**로 쓴다(비율·백분율은 화면이 계산한다). 값이 있으면 `total`·`measured_at`·`source`가 반드시 있어야 하고, `measured_at`은 `updated_at`보다 늦을 수 없다. 하나라도 틀리면 화면은 그 칸을 "측정 중"으로 둔다 (지어낸 수치 방지). `unit`·`note`는 선택. `source`는 저장소 파일 경로나 재현 방법을 쓴다.
- `path`: 저장소 안 파일 경로(`prompts/CHANGELOG.md`). 화면은 저장소 주소에 붙여 링크로 만든다. `..`·절대 경로·주소 문자(`:` `?` `#` `%` `\`)가 든 경로는 링크만 빼고 항목은 보여 준다.
- `answer`: `options`의 0부터 센 번호.
- 형식이 틀린 항목은 화면이 그 항목만 빼고 보여 준다. 검수 체험 `id`가 겹치면 뒤의 것을 뺀다. 최상위 형식(`updated_at`, 각 목록이 배열)이 틀리면 화면 전체에 오류 안내를 낸다.

## 5. 브라우저 저장 (내 조건)

맞춤 추천(#24)에서 고른 조건을 카드 상세(#25)·홈이 같이 쓰도록 브라우저 `localStorage`에 둔다 (`site/js/conditions.js`). 서버로 보내지 않는다.

- 키: `myongji-radar.conditions.v1`. 값: 2절 조건에서 `unknown_terms`를 뺀 JSON.
- **입력 문장과 `unknown_terms`는 저장하지 않는다** (이름·학번이 들어 있을 수 있음).
- 맞춤 추천 화면에 "저장된 조건 지우기"를 둔다 (공용 PC에 학년·학적이 남지 않게). 문장으로 조건을 바꿀 때는 문장이 말한 조건만 바꾸고(제출물을 말하면 제출물 목록을 문장의 것으로), 말하지 않은 조건은 그대로 두며 무엇을 그대로 뒀는지 화면에 알린다.
- 문장을 담은 링크는 `recommend.html#q=문장` (`#` 뒤는 서버로 가지 않는다). 화면은 읽은 즉시 주소에서 지우고, 학생이 칩이나 버튼을 누르기 전까지 저장하지 않는다. 다른 화면으로 갈 때 주소를 보내지 않는다(`referrer` 없음).
- 제출물·마감 기간은 판정이 아니라 목록 필터다. 마감 기간을 고르면 마감일이 없거나 읽을 수 없는 대회는 기간 안인지 알 수 없어 숨기고, 숨긴 수를 따로 알린다.
- 읽을 때 2절 값 범위로 다시 검사하고, 하나라도 틀리면 저장된 조건이 없는 것으로 본다. 형식을 바꾸면 키의 버전을 올린다.
