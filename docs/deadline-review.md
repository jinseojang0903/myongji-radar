# 마감 변경 후보 검토 (#16 다음 단계)

이 도구는 서로 다른 시점에 보존한 검증 결과를 비교해 사람이 볼 **변경 후보 보고서**를 만든다. 공개 카드의 deadline_history를 채우지 않고, 운영 묶음·publisher·이전 관측 상태를 바꾸지 않는다. #14 실제 이미지/첨부 근거 연결 이전에 검토 절차와 비교 조건을 준비하는 단계다.

## 입력 보존과 실행

두 파일은 각각 해당 시점의 원문으로 verifier를 거친 비공개 묶음(`generated_at`, `bundles`)이어야 한다. 오늘 원문으로 어제 묶음을 다시 검증하거나 과거 마감일을 손으로 수정해 전후 파일을 만들지 않는다. 값이 바뀌면 #91 검증 표시도 무효다. 원문·추출 캐시·검증 파일을 각 시점에 백업해 두고 읽기 전용 자료로 취급한다.

`pipeline`에서:

```powershell
.\.venv\Scripts\python.exe -m merger.deadline_review --before data/deadline-snapshots/before.json --after data/deadline-snapshots/after.json --out preview-data/deadline-review.json
.\.venv\Scripts\python.exe -m unittest discover -s tests -p '*deadline_review*.py' -v
```

저장소 내부 출력은 Git이 무시하는 `pipeline/preview-data/` 아래 고정 파일명 `deadline-review.json`만 허용한다. 입력 폴더 하위·site·입력 파일 덮어쓰기는 거부한다. 다른 clone·worktree도 경로의 `.git`을 찾아 같은 정책을 적용한다. 파일명과 강제 종료 시 남을 수 있는 임시 파일은 전 경로 Git 제외 대상이다.

입력은 작성이 끝난 불변 백업을 사용한다. 입력 폴더에 잠금 파일을 만들지 않으므로 읽기 전용 백업도 사용할 수 있다. 실행 중 생산자가 입력을 덮어쓰는 운영 경로는 지원하지 않는다. 출력 폴더만 CollectorLock으로 잠가 동시 쓰기를 막고, 종료 후에는 OS 잠금만 풀리며 출력 폴더의 잠금 파일은 남는다.

## 종료 코드

- **0:** 비교와 보고서 저장 완료, 변경 후보 없음. 신규·철회·비교 보류 항목이 있어도 후보가 없으면 0이다. 보류 사유는 보고서에서 확인한다.
- **1:** 보고서 저장 완료, 사람이 확인할 변경 후보가 하나 이상 있음. 공식 변경 승인이나 실행 실패를 뜻하지 않는다.
- **2:** 잘못된 입력·경로·시점 순서, 출력 잠금 충돌 또는 실행/저장 오류로 중단. 기존 보고서는 유지한다.

도구가 직접 정의한 고정 오류 문구는 표시하되, 외부 입력이나 예상 밖 예외의 내용은 출력하지 않고 예외 종류만 남긴다. 신규·철회 ID는 `added_ids`·`removed_ids`로 구분한다. 식별할 수 없는 묶음은 스냅샷 이름·배열 위치·고정 사유 코드만 `skipped`에 남기고 다른 묶음의 비교를 계속한다.

`added_ids`·`removed_ids`는 비교 가능한 식별자가 한쪽 시점에만 있다는 뜻이다. 실제 신규 게시·철회를 확정하는 값은 아니다.

## 후보와 제외 조건

- 양쪽 모두 현재 내용과 generated_at에 일치하는 verifier 표시가 있어야 한다. 한 그룹에서 여러 묶음이 발견되면 어느 공지를 비교할지 추정하지 않고 제외 사유를 보고한다.
- 동일 공지의 연속된 수정 판 또는 사람이 등록한 같은 그룹의 서로 다른 공지만 비교한다. 원문 판·입력 해시와 생성 모델·프롬프트 조건을 함께 확인한다. 원문 그대로의 재추출, 모델 변경, 빠진 중간 판은 실제 일정 변경으로 기록하지 않는다.
- 연도를 추정하지 않은 found 신청 종료 날짜·시각만 비교한다. 원문 대조 실패·확인 필요·미대조 이미지/첨부는 제외한다. 같은 마감은 후보를 만들지 않는다.
- 서로 다른 공지는 등록 그룹·첫 원문 판·명확한 게시 순서·후속 연장/변경 추출값을 요구한다. 이것도 공식 변경 확정이 아니라 검토할 후보일 뿐이다.

출력의 `proposals[].review_status`는 항상 `needs_review`다. `change`는 현재 공개 Change와 같은 이전 값·새 값·양쪽 출처·확인 날짜를 담지만 공개 history로 사용하지 않는다. 전후 스냅샷 생성 시각과 후보의 원문 버전 ID도 남겨 같은 URL의 서로 다른 판을 찾을 수 있게 한다. `checked_at`은 이 비교를 수행한 한국 날짜이며 실제 변경 게시일을 추정한 것이 아니다. 제외는 고정 사유 코드로 보고하며 원문 인용·연락처는 보고서에 복제하지 않는다. 마감이 그대로인 ID는 정상 결과 `unchanged_ids`로 구분한다.

검증 표시는 검증기가 남긴 내용과 처리 순서의 확인 수단이다. 검증 실패나 대조 불가 묶음에도 붙을 수 있으므로 표시 자체가 인용 검증 성공을 뜻하지 않으며, 위조 방지 서명도 추출값의 의미 일치 보증도 아니다. 사람이 두 출처의 신청 마감 역할과 연장/변경 문맥을 직접 확인해야 한다. 보고서를 verifier/exporter에 직접 넣을 수 없으며 후보를 승인하거나 공개하는 자동 경로도 없다.

## 아직 완료하지 않은 실제 사례

역사 영상 공모전의 9/30 → 10/23은 이전 날짜가 포스터에 있다. #14 이전에는 이 이미지 근거를 자동 대조했다고 할 수 없다. 이번 테스트는 합성 본문·추출값을 사용하며 실제 학교 사례를 검증한 것이 아니다. AI 리터러시의 본선 일정 차이는 신청 마감 변경으로 처리하지 않는다. 실제 근거 검증과 공개 이력 연결은 후속 단계이며 이 도구만으로 #16을 완료하지 않는다.
